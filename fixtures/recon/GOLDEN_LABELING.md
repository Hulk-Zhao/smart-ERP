# 对账金标准夹具标注口径（T201）

> 适用文件：`fixtures/recon/golden/golden_500.json`（夹具）、`fixtures/recon/golden/golden_500_baseline.json`（实测基线）。
> 生成器：`tests/recon/golden_gen.py`；评估器：`tests/recon/golden_eval.py`。
> 数据全部虚构：供应商、物料、单据号均为占位编码，不含任何真实客户或供应商信息。

## 1. 这份文件解决什么

对账准确率如果没有金标准样本，就只是一个没有基线的主张。本文件定义 500 行供应商对账行的**逐行标注答案**与**指标口径**，使「匹配准确率 / 误配率 / 归因准确率 / 无法对账识别率」可以被复跑、被质疑、被回归。

三条纪律：

1. **标注先于实现**：场景按真实业务脏数据形态设计，不为迁就引擎现有能力裁剪。引擎做不到的，标注照写，基线如实报低。
2. **不达标不掩盖**：指标数字只允许由 `golden_eval.py` 从引擎实测产出，禁止改夹具凑数、禁止删场景、禁止放宽容差。
3. **缺失 ≠ 零**：任何缺失字段一律 `null`，不得补 0 或补默认值。

500 行供应商对账行分布在 14 个可独立 `reconcile` 的批次里（同供应商、同期间）。其中 10 个批次应当出结论，4 个批次应当降级为「无法对账」。

| 批次 | 场景 | 供应商行 | 我方行 | 期望批次结论 |
|---|---|---|---|---|
| B01 | 完全匹配 + 一单多行（8 单 × 5 行） | 40 | 40 | 已对账 |
| B02 | 单价差异 20 行 | 40 | 40 | 已对账 |
| B03 | 税率差异 12 行 + 含税/不含税口径 12 行 | 40 | 40 | 已对账 |
| B04 | 报废未扣 12 行 + 部分收货 13 行 | 40 | 40 | 已对账 |
| B05 | 金额四舍五入差 20 行 | 40 | 40 | 已对账（差异可容忍，不应阻断） |
| B06 | 单位换算 20 行（10 行共用单号 / 10 行供应商自有单号） | 40 | 40 | 已对账 |
| B07 | 重复计费：整行重复 5 组 + 同号不同内容 5 组 | 40 | 40 | 待人工复核（重复金额占比 23%，需供应商红冲/说明） |

## 3. 字段定义

### 3.1 `batch.input`（复用 `apps/recon/loader.py` 契约）

| 列 | 含义 | 标注约定 |
|---|---|---|
| `scope.org_id / period / system_ids` | 组织、期间、系统范围（G-05） | 固定 `ORG-GOLDEN` / `2026-10` / `ERP,STATEMENT`；跨月挂账行的行级 `period` 才是 `2026-09` |
| `suppliers` | 本次对账的供应商集合 | 每批 1 个虚构编码 |
| `options.tolerance` | 差异容差 | 固定 `amount=0.01 / price=0.0001 / qty=0.0001`；舍入容差用引擎默认值 `rounding=0.05 / rounding_batch_limit=1.00`（夹具不覆盖，避免为凑指标调参） |
| `master_data.suppliers` | 已绑定供应商 | B13 故意留空，用于验证「禁止按名称自动绑定」 |
| `master_data.items` | 物料主数据 | 每个物料必须有 `base_unit`，否则整批无法对账 |
| `master_data.unit_conversions` | 单位换算（`1 from_unit = factor to_unit`） | 仅 B06 登记 `BOX → PCS ×10`；B12 故意不登记 |

### 3.2 单据行（`our_lines` / `supplier_lines`）

| 列 | 含义 | 标注约定 |
|---|---|---|
| `system` | 来源系统 | 我方 `ERP`，供应商 `STATEMENT` |
| `doc_no` + `line_no` | 单据号与行号 | 行唯一标识 `ref = {system}:{doc_no}#{line_no}`；标签即以 `ref` 为键 |
| `supplier_code` | 供应商编码 | 必须能在主数据中找到 |
| `item_code` | 物料编码 | B11 中 13 行为 `null`（缺编码） |
| `qty` | 数量 | 缺失写 `null`，不写 0 |
| `unit` | 计量单位 | 我方 `PCS`；B06/B12 供应商为 `BOX` |
| `unit_price` | 单价 | 4 位小数；4 位以下不影响判定 |
| `amount` | 金额 | 4 位小数存储；`null` 表示缺失（不参与「金额=数量×单价」校验） |
| `tax_rate` | 税率 | 小数形式，如 `0.1300` |
| `tax_included` | 金额是否含税 | 与 `tax_rate` 一起决定「税率口径」归因 |
| `scrap_qty` | 我方报废数量 | 仅报废场景出现；用于「报废未扣」判定 |
| `period` | 行级期间 | 用于期间相似度与跨月挂账 |

### 3.3 `batch.labels`（逐行标注答案）

`labels.supplier[ref]` 标注供应商行；`labels.our[ref]` 标注「我方有、供应商未列示」的行。

| 列 | 取值 | 含义 |
|---|---|---|
| `scenario` | 见 §2 场景键 | 该行所属脏数据形态，用于场景级准确率 |
| `scenario_tag` | 中文名 | 便于人读 |
| `expected_verdict` | `auto_match` / `review` / `duplicate` / `missing_supplier_doc` / `missing_our_doc` / `no_conclusion` | 该行**应该**得到的处理结论 |
| `expected_our_refs` | `ref` 列表 | 应匹配到的我方行；合并场景含 2 个 `ref`（须聚合） |
| `expected_diff_types` | 七类归因子集 | 应判出的差异类型；空列表表示「不应判出任何差异」 |
| `needs_aggregation` | bool | 拆单/合并：单行对不上单行，需先按单据聚合 |
| `forbid_auto_match` | bool | 合并场景：出现多个候选时必须转人工，不得自动选一个 |
| `tolerated_amount` | 4 位小数 | 可容忍差异金额上限（四舍五入差用）；非 0 即表示该行应由「金额舍入容差」类放行 |
| `note` | 文本 | 该行标注理由 |

`expected_verdict` 与引擎状态的对应关系（评估器实现口径）：

| 标注 | 合格条件 |
|---|---|
| `auto_match` | 有输出行，`our_ref` 等于标注目标，终态 ∈ {已匹配, 待人工}（配对正确，差异是否需人工确认不影响匹配判定） |
| `review` | 终态 ∈ {匹配歧义, 候选待人工, 待人工}；若被自动配对则计「越权出结论」 |
| `duplicate` | 终态 = 重复计费 |
| `missing_supplier_doc` | 终态 = 供应商未匹配 |
| `missing_our_doc` | 终态 = 我方未匹配 |
| `no_conclusion` | 整批终态 = 无法对账，且 `metrics is None`、`lines`、`diffs` 为空 |

## 4. 标注规则（逐场景构造方式）

| 场景 | 构造方式 | 期望匹配 | 期望差异类型 | 依据 |
|---|---|---|---|---|
| 完全匹配 / 一单多行 | 同单号同行号，数量、单价、金额、税率全等 | 该行 | 无 | 基线对照组，必须 100% 正确 |
| 单价差异 | 数量一致，供应商单价 = 我方 ×1.05 | 该行 | 单价不一致 | 调价未生效，差异可按数量×价差还原 |
| 税率差异 | 数量、单价一致，税率 13% vs 6%，金额差 = 基数×税率差 | 该行 | 税率口径 | 同一计税基数的适用税率不同 |
| 含税/不含税口径 | 数量、单价一致，一方含税金额、一方不含税金额 | 该行 | 税率口径 | 口径错位，不是拒付 |
| 报废未扣 | 我方 `qty=100, scrap_qty=4`，供应商按 104 计费 | 该行 | 报废未扣 | 合同按良品结算，投入数计费属多计 |
| 部分收货 | 供应商少计 4 件（我 100 / 供 96） | 该行 | 数量不符 | 未完全收货即结算 |
| 金额四舍五入差 | 数量与单价完全一致，供应商金额按角（1 位小数）取整，单行差 ∈ (0.01, 0.05] | 该行 | **`金额舍入容差`**（容差调整类，不入七类归因分母；`tolerated_amount` 记录差额） | 舍入误差不是争议，不应阻断批次 |
| 单位换算（共用单号） | 供应商按箱（1 箱 = 10 件）报 10、单价 125，共用我方单号 | 该行 | 无 | 有闭合换算关系，换算后完全一致 |
| 单位换算（自有单号） | 同上，但供应商只给自己的发票号 | 该行 | 无 | 检验模糊配能否看穿单位口径 |
| 重复单号（整行重复） | 同单号、同物料、同数量、同单价、同金额列示两次 | 首次正常匹配；第二次 | 第二次：重复计费 | 同一笔业务被计费两次 |
| 重复单号（同号不同内容） | 同单号第二次列示且单价被改动（10 → 10.2） | 首次正常匹配；第二次 | 第二次：重复计费，差异建议必须写出冲突列（`单价 10→10.2`） | 单号相同即同一笔业务，金额改动不能洗白 |
| 拆单 | 我方 1 行（100 件 / 1250 元）被供应商拆成 40+60 两行 | 两行都指向同一我方行，`match_type=aggregated` | 无 | 合计金额一致，属列示方式差异 |
| 合并 | 我方两行（30 / 20 件）被供应商并为一行 50 件 | 该行对应两个我方行，`match_type=aggregated` 且必须转人工 | 无 | 单行对多行，拆分口径不唯一，必须人工确认 |
| 缺单（供应商多计） | 供应商有行，我方无任何对应单据 | 无 | 缺单（金额为正） | 需补单或拒付 |
| 缺单（我方未列示） | 我方有行，对账单完全没有 | 无 | 缺单（金额为负） | 需确认是否上期已结 |
| 跨月挂账 | 我方行期间 `2026-09`，供应商行 `2026-10`，数量单价金额一致 | 我方上月行 | 无 | 期间不同不等于业务不同 |
| 缺物料编码 | 供应商行 `item_code = null` | 整批降级 | 无（不出归因） | 无法确定物料即无法对账 |
| 单位换算缺失 | 供应商 `BOX`、我方 `PCS`，主数据无换算关系 | 整批降级 | 无 | 不许猜换算系数 |
| 供应商未绑定 | 供应商编码不在主数据 | 整批降级 | 无 | 禁止按名称自动绑定 |
| 行数据缺失 | 缺数量 / 缺单价与金额 / 缺单位 | 整批降级 | 无 | 缺失 ≠ 零 |

## 5. 歧义处理规则

1. **拆单**：两行供应商行都指向同一我方行，`needs_aggregation=true`。引擎按「同供应商 + 物料 + 期间 + 单位」分组做合计闭合匹配，两行都标 `match_type=aggregated` 并带 `aggregate_refs`；拆单合计闭合可自动放行，但必须能与直配区分。
2. **合并**：一行供应商行指向两个我方行，`forbid_auto_match=true`。引擎同样标 `aggregated`，但 `status=待人工`（`MERGED_CONFIDENCE=0.85`）且 `aggregate_refs` 列全被覆盖的我方行；自动挑其中一行即为「越权出结论」。
3. **四舍五入**：仅当「数量一致 + 单价一致 + 单行金额差 ≤ `tolerance.rounding`（默认 0.05）」才计入 `DiffType.ROUNDING_TOLERANCE`；该类别在差异明细可见但不生成差异单、不计入七类归因分母。超过 0.05、或整批累计超过 `rounding_batch_limit`（默认 1.00 元）/ `0.5%` 时不得放行，转人工。
4. **同一单据号二次列示**：不论内容是否被改动，第二次一律标注「重复计费」。业务上单号是业务唯一键，金额被改只是掩盖方式；差异建议必须逐列写出冲突（数量/单位/单价/金额/税率），便于人工定位。
5. **整批降级**：缺编码、缺换算、供应商未绑定、行数据缺失一律「无法对账」，不逐行补猜、不部分出结论（`01-技术架构.md` I-4）。
6. **一条脏数据只标一个主场景**：同时具备多个特征时，取「最能解释差异的那个原因」作为主场景（例如报废与数量同时变动时标报废未扣），避免同一行被重复计入多个分母。

## 6. 指标口径

所有指标的分母一律取**标注期望**，不取引擎实际输出行数（否则漏判会被隐藏）。

| 指标 | 定义 | 基线文件字段 |
|---|---|---|
| 匹配准确率 | 标 `auto_match` 的行中，`our_ref` 等于标注目标的比例 | `match.accuracy` |
| 误配率 | 标 `auto_match` 的行中，被我方错误配对（`our_ref` 存在但不等于目标）的比例 | `match.mismatch_rate` |
| 未配数 | 标 `auto_match` 的行中，未被配对（未匹配/候选/歧义/无输出）的行数 | `match.missed` |
| 归因准确率 | `expected_diff_types` 非空的行中，引擎判出的差异类型集合与标注**完全相等**的比例（`金额舍入容差` 属容差调整类，不入分母） | `attribution.accuracy` |
| 无法对账识别率 | 期望降级的批次/行中，实际返回「无法对账」且无指标无明细的比例 | `no_conclusion.rate` |
| 误判已对账 | 批次出「已对账」但批内存在任一标注判错行的批次数 | `safety.false_auto_pass_batches` |
| 误判无法归因 | 标注不需要归因的行，被引擎塞进 `unattributed` 的数量 | `safety.false_unattributed_refs` |
| 应转人工成功率 | 标 `review` 的行中，未被自动配对的比例 | `review.rate` |
| 聚合场景准确率 | `needs_aggregation=true` 的行中合格的比例（宽松口径：配对到我方行即可） | `match.needs_aggregation` |
| 聚合匹配识别率 | `needs_aggregation=true` 的行中，`match_type` 实为 `aggregated` 且 `our_ref` 命中标注的比例（严格口径，拆单/合并分别统计） | `aggregation.*` |
| 舍入容差识别率 | `tolerated_amount ≠ 0` 的行中，引擎产出 `金额舍入容差` 且所在批次为「已对账」的比例；并单列仍被误判为无法归因的行 | `rounding_tolerance.*` |
| 同号冲突定位率 | `duplicate_same_doc` 的行中，终态为「重复计费」且差异建议包含冲突列的比例 | `duplicate.conflict.*` |

PRD 目标：FR-103 匹配率 ≥ 92%，FR-104 归因准确率 ≥ 85%（`docs/product/PRD.md`）。基线文件中 `prd_targets` 直接给出达标与否，不达标时保留原值并写明原因。

复跑：

```bash
python tests/recon/golden_gen.py     # 重生成夹具（确定性）
python tests/recon/golden_eval.py    # 重算并写入基线
python tests/recon/golden_eval.py --check   # 只校验基线是否漂移
python -m pytest tests/recon -q      # 结构校验 + 基线可复现回归
```

场景级准确率（19 类）本轮全部为 1.0，包括此前未达标的 `duplicate_same_doc`（0/5 → 5/5）、`split_invoice`（5/10 → 10/10）、`uom_conversion`（10/20 → 20/20）。

### 7.2 引擎改了什么，为什么是改进而不是调参

1. **新增 `DiffType.ROUNDING_TOLERANCE`（金额舍入容差）**：数量与单价**完全一致**、仅金额按角取整产生差额时，才按容差放行；默认单行 0.05 元（按角取整的最大误差）、单批累计 1.00 元或占比 0.5%。超出任一上限即 `rounding_escalated` 转人工。该类别在差异明细可见、可审计，但不生成差异单（不会向供应商重复要钱），也不进七类归因分母。**没有放宽任何既有容差**（`amount` 仍为 0.01）。
2. **去重键改为业务唯一键**：`(供应商, 期间, 单据号, 物料)` 分组，第二条起判重复；同号同物料但内容不一致时标 `conflict` 并逐列写出冲突（如 `单价 10→10.2`），不再落成「缺单」。整行完全相同的跨单号重复仍保留 `exact` 判定。
3. **新增聚合匹配层**：拆单（多供应商行 → 我方一行）按同供应商 + 物料 + 期间 + 单位的合计闭合匹配，标 `aggregated` + `aggregate_refs`；合并（供应商一行 → 我方多行）同样标 `aggregated` 但强制 `待人工`。不做逐行归因，避免拆单分行金额被误判为数量不符。
4. **评分前单位换算**：`_comparable` 先用主数据把供应商数量/单价折算到我方单位口径再打分；不可换算时数量/单价按中性 0.50 降权并把总分**封顶 0.65**（低于 0.70 自动匹配闸门），候选原因写明 `[UNCONVERTIBLE]`，与「业务键相似度低」区分。

### 7.3 未回归声明

原本达标的 16 类场景（完全匹配 236、跨期 20、单价差异 20、税率 12+12、报废 12、部分收货 13、缺单 10+10、无法对账 4 批）改后仍为 1.0；`误配率` 与 `误判已对账批次` 保持 0；归因分母从 99 行未变为 99 行，说明提升来自识别而不是缩小分母。

## 8. 已知能力边界（本次实测暴露，未在夹具中掩盖）

本轮已关闭以下四项（改前描述保留在 §7.1 对比列）：

1. ~~拆单/合并缺少聚合~~：已加聚合匹配层，拆单/合并均标 `match_type=aggregated`。
2. ~~跨单位模糊匹配不可见~~：评分前先按主数据换算，`uom_conversion` 20/20。
3. ~~金额四舍五入差无归类~~：新增 `金额舍入容差`，B05 已可对账。
4. ~~同单号不同内容的重复识别不了~~：去重键改业务唯一键并输出冲突列。

仍然存在、必须如实说明的边界：

1. **`DiffType.UOM` 在 `reconcile` 路径仍不可达**：缺换算关系会先被 `check_readiness` 拦截为整批「无法对账」，因此「单位换算」永远以「降级」而非「归因」形式出现（B12 的 25 行属于正确降级）。「不可换算 → 候选 + `[UNCONVERTIBLE]` 原因」分支只在直接调用 `match_lines` 时可达，由单元测试覆盖，不代表真实批次已覆盖。
2. **舍入容差只覆盖「数量、单价完全一致」**：若数量或单价本身有小差（但在各自容差内），仍走七类归因或人工，不会被打成舍入容差。这是有意收窄，避免容差类别成为兜底黑洞。
3. **聚合匹配要求合计精确闭合**：金额/数量按 4 位小数精确相等才聚合；合计差 0.01 元以内也不放行（避免把真实差异洗成拆单）。合并方向枚举上限为 4 个候选、3 行组合，超出即落人工。
4. **差异率闸门仍会掩盖归因错误**：B07 结论「待人工复核」来自重复金额占比 23% > 20%，不能据此认为逐行归因正确——评估器因此按行独立判定，不看批次结论。
5. **基线全绿≠生产可用**：500 行是设计好的确定性样本，19 类场景各 5~236 行；对未建模的脏数据（一单多物料混拆、跨供应商代付、部分红冲）没有覆盖，需另造样本。

### 10.1 留出集怎么切

`tests/recon/golden_holdout_gen.py`（确定性、不依赖引擎、不改 `golden_500.json`）：

- 调参期间不看留出集；引擎（`apps/recon/*`）冻结后才允许第一次评估，且**只用于报数，不据此改规则**。

### 10.3 为什么留出集仍是 1.0000，以及它不能说明什么

留出集与训练集**同源**（冻结夹具的子集），而引擎的绑定/归因是逐行确定性规则，因此任何子集都会得到与训练集相同的判定——本轮实测 1.0000 是预期结果，不是新证据。两处可见差异说明它确非同一份数据：B07 批次级差异率 0.2000（训练集 0.2300），B07 在留出集中结论为「已对账」、训练集为「待人工复核」，差别来自抽样后重复金额占比跨过 20% 闸门。**不得**用留出集满分对外承诺自动化率。

|---|---|---|---|

本轮修复内容（对应两条 P0）：

1. **P0-1 单位守门**（`apps/recon/matching.py`）：单位不同（仅忽略大小写/空白）必须命中主数据换算，且换算后「数量与金额同时闭合」才允许自动匹配；直配层同样受此约束——以前同单号直接给 1.00，会把 100 BOX 当 100 PCS 放行。不满足时封顶 0.65、只给候选，原因码写明「单位不一致」及其可核对数字。

### 10.7 已知限制：1.0 不是生产水平

以下限制在获得真实数据前无法消除，任何对外承诺都必须先看这一节：

1. **留出集与训练集同源**（冻结夹具的子集）。引擎是逐行确定性规则，任何子集都会得到与训练集相同的判定，因此留出集 1.0000 不构成泛化证据。
2. **对抗集只有 10 个构造用例 / 11 行**，覆盖 6 类脏数据。它能证明「这两类已知缺陷不再崩溃、不再越权放行」，不足以估计真实自动化率；样本量小，换个构造就可能暴露新问题。
3. **真实单据分布未进入样本**：供应商对账单格式、税率与含税口径、拆并单习惯、OCR 质量、主数据完整度都来自虚构夹具，真实数据的长尾远大于 19 类场景。
4. **没有真实标签**：所有期望值都是我们自己标的；「自动放行且结论正确」的比例从未在人工对账结论上验证过。

**下一步：拿真实数据（路径与前置条件）**

1. **从哪来**：客户上线前提供 1~3 个完整对账期的数据——我方 ERP 的应付/入库明细 + 供应商对账单（Excel/PDF/扫描件均可），至少覆盖 5 家供应商、≥500 行；优先挑历史上出现过差异、拆并单多、单位混用的供应商。
2. **需要客户提供**：
   - 行级字段：单号、行号、供应商、物料编码、数量、单位、单价、金额、税率、期间、含税标记；
   - 主数据：供应商清单、物料清单（含基础单位）、单位换算关系（换算系数错一位是本项目已知高危场景，必须给全）；
   - 一份人工对账结论（哪怕只有 20~50 行），作为真实标签与验收基线。
3. **脱敏口径**（我方只收脱敏结果，映射表由客户保管）：
   - 供应商/客户名称→代号（SUP-001），统一社会信用代码、银行账号、联系人、电话、地址全部删除；
   - 单据号按规则重编，但保留「同号 / 跨期同号」关系，并保留 0/O、1/l 等易混字符的原始形态；
   - 物料编码与名称→代号，**单位与换算关系不得改动**（它正是要测的对象）；
   - 金额、数量按同一比例缩放或做位序替换，保留小数位与舍入误差形态，确保差异率与量级关系不变；
   - 保留原始脏数据（全角字符、OCR 错字、多余空格、重复行、缺失字段），**不得先清洗再交付**；
   - 签署数据处理附件，明确用途仅限对账评估、留存期限与销毁方式。
4. **评估口径**：以人工对账结论为标签，报「自动放行且结论正确行数 / 总行数」作为自动化率；**错放行的行按 0 计**，不能只报放行率。同时报误配率、无法对账率与转人工占比。
5. **纪律**：首批真实数据作为测试集冻结，先跑后调；一旦用于调参即并入训练集，另取下一批，并记录「第几轮真实数据」。
