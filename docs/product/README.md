## 一页速览

| 项 | 结论 |
|---|---|
| **我们是什么** | 存量异构系统之上的**可审计业务执行层**。不换 ERP、不做入口，做跨系统的"最后一公里"写入 |
| **服务谁** | 离散制造（电子组装/装备/汽配），营收 3–20 亿，2–5 个工厂，≥2 套异构系统 + 自研 MES |
| **第一楔子** | 委外加工费 + 采购三单的**跨系统对账与结算闭环**（月度高频、跨 5 个系统、写入风险可控、KPI 可直接计费） |
| **三条主卖点** | M1 跨系统闭环（答业务）｜M2 可审计可回滚（答安全）｜M3 结果计费且封顶（答财务） |
| **凭什么由你聚合** | 不抢入口而是寄生在企微/钉钉；只做跨系统（跨系统数 < 2 的 Agent 不立项）；审计做成产品对象；厂商中立 |
| **架构一句话** | 五层：交互 / Agent / 连接与聚合 / 薄业务内核 / 模型与数据。硬边界：不自建总账、不自建库存台账 |
| **怎么收钱** | 平台订阅（按连接器 × 组织，不按席位）+ 结果费（按客户已有 KPI，年度封顶）+ 一次性诊断与上线 |
| **MVP 边界** | 2 个 Agent（对账、单据录入）+ 审计回滚 + 6 个连接器 + 7 个界面；**不做**总账/税务/资金/排程/报价/移动 App |
| **最大风险** | MCP 层安全（2026-04 RCE）、厂商反制、实施失败、归因争议——各自有机制而非口头承诺 |

## 评审需要拍板的 6 个决定

| # | 决定 | 备选 | 我们的建议 | 在哪节 |
|---|---|---|---|---|
| 1 | 是否接受"不自建总账、不自建库存台账"的硬边界 | 做完整 ERP / 只做执行层 | 只做执行层 | 架构 §4.3、风险 §9 |
| 2 | 第一楔子选"对账"还是"车间异常" | 对账（财务运营，风险低）/ 异常（制造，差异化更强但数据门槛高） | 先对账，Phase 3 再做异常 | 定位 §4 |
| 3 | MVP 是否关闭 W3（资金/凭证）写入 | 关闭 / 允许少量 W3 | 关闭，安全评审优先 | 架构 §6 |
| 4 | 是否接受"跨系统数 < 2 的 Agent 不立项"的产品纪律 | 接受 / 按客户需求放开 | 接受，否则会退化为集成商 | 定位 §6.2 |
| 5 | 定价是否采用"平台订阅 + 结果费封顶" | 纯订阅 / 按动作 / 订阅+结果 | 订阅 + 结果（默认 R1 有效对账行口径） | 商业 §1 |
| 6 | 客户准入是否排除小微与流程制造 | 排除 / 全客群 | 排除，MVP 只做电子组装 | 定位 §3.2 |

## 术语表（跨文档统一口径）

| 术语 | 定义 |
|---|---|
| **Agent 工单** | 一次 Agent 执行的完整业务单据：计划、步骤、前像后像、审批链、影响面、可回滚 |
| **写入等级 W0–W3** | W0 只读建议 / W1 草稿 / W2 低风险过账 / W3 资金与凭证（MVP 禁止） |
| **权威源（Source of Truth）** | 某个数据域的最终裁定系统；我们只在"对账账、执行账、审计台账、指标基线"上是权威源 |
| **对账账** | 跨系统事务的应收/应付/已收/已付/差异五列对照 |
| **执行账** | 跨系统事务的生命周期记录，回答"到底办完没有、卡在谁那里" |
| **接入级别 L1/L2/L3** | L1 官方 API / L2 只读副本与中间表 / L3 语义化 RPA 兜底 |
| **结果单元 R1/R2/R3** | 结果计费的三个可选锚点：有效对账行 / 差异收敛 / 周期达成 |
| **基线协议** | 上线前冻结的指标基线，作为结果计费的合同附件 |
| **影子运行** | 只产出建议不写入的试运行阶段，用于验证准确率 |
| **熔断** | 失败率超阈值时自动降级为只读建议的机制 |
