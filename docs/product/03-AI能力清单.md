# AI 能力清单

> 版本：v0.1（待评审）
> 本文定义 8 个预置 Agent。每个 Agent 的写法统一为：解决什么问题 → 输入 → 输出 → 写入哪些系统（含写入等级）→ 失败与回滚 → 人工复核点 → 怎么衡量是否值得买。
> 写入等级定义见《02-产品架构》§6；MVP 阶段任何 Agent 都不得进入 W3。

---

## 0. 准入标准（不满足就不立项）

每个 Agent 立项时必须通过五项检查，任一项不通过直接否决：

| # | 检查项 | 判据 |
|---|---|---|
| 1 | **跨系统** | 必须跨越 ≥ 2 个系统，且缺任一系统则业务无法闭环。（对应定位文档 D2 产品纪律） |
| 2 | **可回滚** | 每个写动作必须能声明补偿动作；无法补偿的动作只能进 W0 |
| 3 | **可复核** | 必须存在一个人工复核点，且复核人能看懂"为什么这么判"（证据可下钻到原单字段） |
| 4 | **可度量** | 必须绑定一个客户已有的 KPI，能在上线前后做同口径对比 |
| 5 | **非原厂能力** | 原厂在自己域内能独立完成的场景不做（如金蝶域内的费用审核） |

### 0.1 总览

| 编号 | Agent | 一句话职责 | 跨系统数 | 最高写入等级 | 上线阶段 | 计费锚点 |
|---|---|---|---|---|---|---|
| A1 | 对账 Agent | 把「供应商 × 期间」的账对平 | 5 | W1 | MVP | 对账差异率、完成批次数 |
| A2 | 单据录入 Agent | 把纸面/PDF/图片单据变成系统里的正确单据 | 3 | W1 | MVP | 单据直通率、录入工时 |
| A3 | 采购比价 Agent | 在"能用"的供应商里选"该用"的那家 | 3 | W1 | Phase 2 | 采购价差、比价覆盖率 |
| A4 | 库存与齐套 Agent | 在缺料发生前告诉你是谁缺、缺多少、怎么补 | 3 | W2 | Phase 2 | 齐套率、缺料停线小时 |
| A5 | 生产排程 Agent | 给出可执行、可解释、可协商的排程方案 | 3 | W0 | Phase 3 | 准交率、换型次数 |
| A6 | 异常处置 Agent | 把车间异常变成一串跨系统的补救动作 | 4 | W1 | Phase 3 | 异常闭环时长、停线损失 |
| A7 | 报价 Agent | 用真实成本结构算出一个敢报的价 | 3 | W1 | Phase 3 | 报价周期、毛利偏差 |
| A8 | 月结辅助 Agent | 把月末的暂估、分摊、差异归集做掉 | 4 | W1 | Phase 2 | 月结天数 |

**为什么 A1/A2 先进 MVP**：它们共同覆盖"数据进得来 + 账对得平"，是其他六个 Agent 的事实基础。A3–A8 全部依赖"物料/供应商/价格"的干净映射与"对账账"的准确性，跳过 A1/A2 直接做排程或报价，会在数据泥里翻车（报告 §4.3 把数据质量列为 AI 项目失败首因之一）。

## A1 对账 Agent（MVP · 核心楔子）

### 解决什么业务问题

月末财务与采购要在 3–5 天内把几十上百个供应商的账对平：ERP 里是采购/委外订单与入库，MES 里是报工与报废，WMS 里是收发料，供应商发来的是 Excel 或 PDF 对账单，加工费还涉及损耗率与单价阶梯。今天的做法是人肉三栏比对 + 微信追问，结果是月结拖到 12 天以上、差异说不清、付款靠感觉。
（痛点依据：报告 §4.1 CFO"月结太慢、数据不可信"；§5.1-2 系统分散）

### 输入

| 来源 | 内容 | 形态 |
|---|---|---|
| ERP | 采购订单、委外订单、入库单、退货单、应付余额 | API / 只读副本 |
| MES | 委外件的报工数量、报废数量、工序完成状态 | API |
| WMS / 库存 | 委外发料、委外收货、线边退回 | API / 中间表 |
| 供应商 | 对账单、送货单、加工费明细 | PDF / Excel / 图片 / IM 文件 |
| 主数据 | 物料单位换算、供应商编码映射、加工费单价协议 | ERP + 合同附件 |

### 输出

1. **对账批次结论**：每个「供应商 × 期间」一条，状态为 已平 / 有差异 / 待补单据 / 无法对账（数据缺失）。
2. **差异清单**：逐行给出差异类型、差异金额、差异数量、责任方（我方/供应商/系统）、建议处置。
3. **差异归因**（七类）：单价不一致 / 数量不符（多发少发）/ 报废未扣 / 单位换算错误 / 税率或含税口径 / 缺单（有收货无订单）/ 重复计费。
4. **付款申请草稿**：仅对"已平"或"差异已确认"的批次生成，附对账结论链接。

### 写入哪些系统

| 系统 | 动作 | 等级 |
|---|---|---|
| 我们的对账账 | 写入对账批次、差异项、归因标签 | 自有对象 |
| ERP 应付 | 创建付款申请**草稿**（不提交审批、不过账） | W1 |
| ERP | 创建差异处置单（补单申请/退货申请） | W1 |
| 供应商协同记录 | 写入对账确认状态与争议点 | 自有对象 |
| IM | 向采购/供应商对接人推送待确认卡片 | 通知类（不计入写入等级） |

**明确不做的写入**：不修改已入库单据、不调整已过账凭证、不发起实际付款、不修改供应商银行信息。

### 失败与回滚

| 失败模式 | 检测方式 | 处理 | 回滚 |
|---|---|---|---|
| 对账单解析失败（扫描件模糊/格式异常） | 抽取置信度低于阈值 | 不进自动流程，整批转人工队列并告知缺哪几个字段 | 无需回滚（未写入） |
| 单位换算错误导致数量差 1000 倍 | 数量差异超过业务合理区间（如 >10 倍） | 中止该行，标记"疑似换算错误"，不生成付款草稿 | 删除已建草稿 |
| 匹配到错误的订单（同物料同数量多单） | 匹配候选 ≥2 且置信度接近 | 不下结论，输出候选列表交人裁决 | 无需回滚 |
| 付款草稿创建成功但金额错误 | 写入后校验：草稿金额 = 对账结论金额 | 自动删除草稿并重算；连续 2 次失败则熔断该供应商 | 自动删除（W1 可逆） |
| ERP 接口超时/限流 | 网关重试 3 次后失败 | 工单停在"执行中"，保留断点，限流恢复后从断点续跑 | 已完成步骤保留，未完成步骤不执行 |
| 供应商对账单在我方结论之后又变更 | 文件哈希变化 | 作废旧结论，重开批次，旧批次留档 | 旧对账批次置为"已作废"，不删除 |

**补偿动作声明**：`delete_payment_draft(id)`、`cancel_discrepancy_ticket(id)`、`void_reconciliation_batch(id)`。

### 人工复核点

1. **差异确认**（必复核）：所有金额差异 > 500 元或差异率 > 2% 的行，必须由采购或财务逐条确认归因，Agent 只给建议。
2. **付款草稿提交**（必复核）：草稿生成后不自动提交，由财务在 ERP 或我们的审批页确认。
3. **首次合作供应商**（必复核）：新供应商前 3 个期间全部人工复核，之后可放宽。
4. **无法对账批次**（必处理）：Agent 不说"对不上"，必须说清"缺哪张单、找谁要"。

### 怎么衡量

| 指标 | 口径 | MVP 目标 |
|---|---|---|
| 对账差异率 | 差异金额 / 对账总金额 | 相对基线下降 ≥ 30% |
| 单供应商对账工时 | 从取数到出结论的人工分钟数 | 下降 ≥ 60% |
| 差异归因准确率 | 人工确认的归因与 Agent 建议一致的比例 | ≥ 85% |
| 付款草稿一次通过率 | 未经修改即被财务采纳的比例 | ≥ 80% |

## A2 单据录入 Agent（MVP）

### 解决什么业务问题

采购、仓库、财务每天把送货单、委外领料单、发票、对账单手动敲进系统。工作本身不创造价值，但错了要返工，且错误在月末才暴露。这是典型的"高频、低判断、强格式"场景，也是 Agent 最容易做出可信效果的入口。

### 输入 / 输出

- **输入**：PDF / 图片 / 扫描件 / IM 里的文件 / 邮件附件；目标单据类型的字段模板；主数据（物料、供应商、单位）。
- **输出**：结构化字段 + 每个字段的置信度 + 原文坐标（可点击回跳影像）+ 匹配到的系统主数据候选 + 生成的单据草稿。

### 写入哪些系统

| 系统 | 动作 | 等级 |
|---|---|---|
| ERP | 创建采购入库单/委外领料单/发票登记的**草稿** | W1 |
| 我们的单据中心 | 写入抽取结果、置信度、影像引用 | 自有对象 |
| 文件存储 | 归档原始影像（不可变） | 自有对象 |

### 失败与回滚

| 失败模式 | 处理 | 回滚 |
|---|---|---|
| 关键字段缺失（数量、单价、供应商） | 不建单，进"待补录"队列，标出缺失字段 | 无需回滚 |
| 物料匹配歧义（同名不同规格） | 给 Top3 候选，不自动选 | 无需回滚 |
| 重复录入（同一张单被扫两次） | 用"供应商 + 单号 + 金额 + 日期"四元组做幂等键，命中即拒绝 | 拒绝创建 |
| 建单后字段错（人复核发现） | 直接改草稿或删除重建 | 删除草稿（W1） |

### 人工复核点

1. 置信度低于 0.85 的字段高亮，必须人确认。
2. 金额 > 10 万元的单据必须复核全部行项目。
3. 首次出现的供应商/物料编码必须人工绑定映射。

### 怎么衡量

单据直通率（无需人工修改即被采纳的比例）≥ 70%；单张录入工时下降 ≥ 70%；抽取字段准确率 ≥ 97%（数值类要求更高）。

## A3 采购比价 Agent（Phase 2）

### 解决什么业务问题

采购员比价靠经验和微信问价，历史价格散在 ERP 和 Excel 里，替代料关系在老师傅脑子里。结果是同一种料在不同工厂、不同时间价差能到 20%，且没人能解释为什么选了这家。
（依据：报告 §6-卖点1 指出跨系统"过程"缺失；§4.3 数据口径不一）

### 输入 / 输出

- **输入**：请购需求（物料/数量/交期）、历史采购价与成交记录、供应商报价（邮件/微信/Excel）、供应商绩效（交期、质量、历史差异率）、替代料关系、当前库存与在途。
- **输出**：比价矩阵（供应商 × 单价 × 交期 × 历史履约 × 综合得分）、推荐结论与理由、风险提示（单一供应商、价格异常高于历史中位数 15%）、下单建议草稿。

### 写入哪些系统

| 系统 | 动作 | 等级 |
|---|---|---|
| ERP | 创建询价单/采购订单**草稿** | W1 |
| 我们的比价库 | 写入报价快照、比价结论、价格基线 | 自有对象 |
| 供应商协同 | 写入询价发出记录与回复 | 自有对象 |

### 失败与回滚

- 报价口径不一（含税/不含税、含运费/不含运费）：先归一化再比较，归一化失败则拒绝比价并说明缺哪个口径。
- 供应商报价过期：超过有效期直接排除，并在结论里注明。
- 历史价格异常（历史本身是错的）：Agent 不做"清洗历史"，只标注"历史价方差过大，建议人工确认基线"。
- 回滚：草稿订单可删除；比价结论可作废，但保留留档。

### 人工复核点

1. 所有比价结论必须由采购确认后才转订单（W1，不自动下单）。
2. 单一供应商或价格高于历史中位数 15% 时强制升级审批。
3. 首次合作的替代料必须由工艺/品质确认可用性——Agent 不做技术判断。

### 怎么衡量

比价覆盖率（走比价流程的采购金额占比）≥ 60%；同料价差收敛度；采购降本金额（可归因部分）。

## A4 库存与齐套 Agent（Phase 2）

### 解决什么业务问题

排产排了，料不齐；料到了，在另一个厂；调拨了，账没动。齐套检查靠 Excel，缺料发现得太晚，最后靠紧急采购与空运救火。

### 输入 / 输出

- **输入**：生产计划/工单、BOM（多级）、各厂各仓实时库存、在途采购、已分配未发料、替代料、安全库存与补货策略。
- **输出**：齐套缺口清单（工单 × 物料 × 缺口数量 × 最早可用日期）、缺口归因（未采购/在途延迟/被其他工单占用/账实不符）、补货与调拨建议、风险工单清单（会影响交期的）。

### 写入哪些系统

| 系统 | 动作 | 等级 |
|---|---|---|
| 我们的执行账 | 写入齐套结论、缺口、建议 | 自有对象 |
| ERP/WMS | 创建调拨申请草稿、采购申请草稿 | W1 |
| 库存分配 | 按规则回写"预留/占用"标记 | W2（有阈值审批） |

### 失败与回滚

- 账实不符（系统有、实物无）：Agent 不能自行调账，输出"疑似账实不符"清单，交仓库盘点。
- BOM 断链（多级 BOM 缺子件）：拒绝给出齐套结论，输出断链位置。
- 预留回写导致其他工单缺料：预留动作必须带优先级规则，冲突时按订单优先级裁决；错误预留可撤销（W2 可逆）。
- 回滚：撤销预留标记、删除调拨/采购申请草稿。

### 人工复核点

1. 预留调整（影响其他订单）必须由计划员确认。
2. 紧急采购建议必须由采购确认价格与交期。
3. 账实不符清单一律人工处理。

### 怎么衡量

齐套率提升；缺料导致的停线小时下降；紧急采购金额占比下降。

## A5 生产排程 Agent（Phase 3）

### 解决什么业务问题

多品种小批量、插单频繁，排程靠计划员 Excel + 经验，排完就过期。客户问"这单什么时候能交"，答不出来。

### 输入 / 输出

- **输入**：工单池（含优先级、交期）、工艺路线与标准工时、设备/工作中心能力与日历、模具/工装约束、人员班次、物料齐套状态、换型时间矩阵。
- **输出**：可执行排程方案（甘特 + 工单序列 + 预计完工日）、瓶颈说明、插单影响的定量评估（"插这单会让哪 3 单延期几天"）、可协商选项（加班/外协/拆批的代价对比）。

### 写入哪些系统

| 系统 | 动作 | 等级 |
|---|---|---|
| 我们的执行账 | 写入排程版本、方案对比、影响评估 | 自有对象 |
| MES / ERP | **只读**工单与能力数据；**不写**工单时间 | W0 |

**为什么最高只到 W0**：排程是全厂最敏感的计划，且求解器输出与现场约束总有偏差。让 Agent 直写工单日期，一次事故就会失去整个工厂的信任。我们的价值是"给出可解释的方案 + 定量影响"，由计划员一键采纳（采纳动作走人工发起的标准写入，不计入 Agent 写入）。

**技术路线**：求解用确定性内核（Frepple 路线，报告 §3.2 称其为开源 APS 最成熟内核），LLM 只负责三件事：把自然语言约束翻译成求解参数、解释方案为什么这样排、生成协商话术。**不用 LLM 直接排程。**

### 失败与回滚

- 无可行解（交期全部无法满足）：输出"最小违约方案"并明确列出必须牺牲哪些订单，而不是假装有解。
- 求解超时：降级为"局部重排"（只重排未来 3 天），并告知降级原因。
- 数据缺失（标准工时缺失）：用历史实际工时估算并标注置信度，缺失率 > 30% 时拒绝出方案。
- 回滚：排程方案是版本化对象，可回退到任一历史版本；因不写 MES，无需系统回滚。

### 人工复核点

1. 所有方案必须由计划员采纳后才生效（强制 W0）。
2. 影响交期的方案必须抄送销售/客服。
3. 首次上线的前 8 周为影子运行，只对比不采纳。

### 怎么衡量

准交率（OTD）；计划员排程工时；换型次数；插单响应时间（从"问"到"给出影响评估"的分钟数）。

## A6 异常处置 Agent（Phase 3）

### 解决什么业务问题

车间出事（缺料、品质异常、设备停机、供应商延期），处理方式是打电话 + 微信群 + 手工改单。异常处置是最能体现"跨系统写入"价值的场景，因为它天然要在 ERP（改单/改期）、MES（改派/报工调整）、采购（补料/催料）、委外（转移）之间来回。这也是原厂 Agent 最覆盖不到的地方——它跨的是"别人家的系统"。

### 输入 / 输出

- **输入**：异常事件（MES 报警、质检不合格、设备停机、供应商延期通知、缺料预警）、受影响工单与订单、可用资源（替代设备/替代料/外协产能）、历史同类异常处置记录。
- **输出**：处置方案（3 个以内，含代价对比：延期 X 天 / 成本增加 Y / 需外协 Z）、推荐方案与理由、需要执行的跨系统动作清单、影响客户清单（哪些订单会延期）。

### 写入哪些系统

| 系统 | 动作 | 等级 |
|---|---|---|
| 我们的执行账 | 写入异常单、处置方案、决议、闭环状态 | 自有对象 |
| ERP | 工单改期/改量草稿、采购申请草稿 | W1 |
| MES | 工单改派、报工调整申请 | W1（需车间主管确认） |
| 委外协同 | 创建委外转移单草稿 | W1 |
| IM | 通知销售/客服/供应商 | 通知类 |

**等级克制的原因**：异常处置涉及生产承诺与客户交期，一次错误改期会连锁影响交付。全部动作停在草稿，由人确认后生效。

### 失败与回滚

| 失败模式 | 处理 | 回滚 |
|---|---|---|
| 方案依赖的资源实际不可用（外协厂没产能） | 执行前先校验资源可用性（preview 阶段），不可用则不生成动作 | 无需回滚 |
| 多系统部分成功（ERP 改期成功、MES 改派失败） | Saga 逆序补偿：撤销 ERP 改期草稿 → 重试 MES → 仍失败则整单转人工 | 自动补偿 |
| 客户已确认新交期后方案被推翻 | 不自动改已对外承诺的交期，升级为人工决策 | 仅告警 |
| 同类异常反复触发（同一设备 24h 内 3 次） | 熔断该规则，转为"根因分析任务"，不再自动出方案 | 不适用 |

### 人工复核点

1. 涉及客户交期变更的方案必须由计划 + 销售共同确认。
2. 委外转移必须由采购确认价格。
3. 所有 W1 写入必须由车间主管或计划员确认后生效。

### 怎么衡量

异常闭环时长（从发生到关闭）；停线损失金额；异常重复率；销售被"突然通知延期"的次数。

## A7 报价 Agent（Phase 3）

### 解决什么业务问题

非标件报价靠老师傅估工时、估损耗、估外协价，报快了亏、报慢了丢单。报价的历史依据散在 Excel、邮件、老系统里，新人接不上。

### 输入 / 输出

- **输入**：客户询价（图纸/规格/数量/交期）、相似历史订单与报价、BOM 与工艺路线、标准工时与实际工时偏差、材料时价、外协价、汇率、良率与损耗历史、毛利底线策略。
- **输出**：成本拆解（材料/工时/外协/制造费用/损耗/运费/税率）、三档报价（保底价/建议价/理想价）、毛利敏感性分析（材料涨 5% 时毛利变化）、相似订单对标、报价单草稿。

### 写入哪些系统

| 系统 | 动作 | 等级 |
|---|---|---|
| 我们的报价库 | 写入报价版本、成本构成、假设条件 | 自有对象 |
| ERP / CRM | 创建报价单**草稿** | W1 |
| 知识库 | 沉淀"报了没中/中了亏了"的复盘记录 | 自有对象 |

### 失败与回滚

- 无相似历史（全新品类）：明确输出"无历史参照，置信度低"，只给成本区间不给点估计。
- 图纸无法解析：转人工估价，不做猜测。
- 报价已发出后成本变化：不修改已发出版本，生成新版本并标注差异（版本不可变）。
- 回滚：草稿报价单可删除；已发出版本只能作废并新建，永不复用编号。

### 人工复核点

1. 报价必须由销售负责人 + 成本会计双签（涉及毛利承诺）。
2. 低于毛利底线的报价强制升级到总经理。
3. 新客户首单报价必须人工全量复核。

### 怎么衡量

报价周期（询价到出价的小时数）；报价毛利率与实际的偏差；中标率变化；报价返工率。

## A8 月结辅助 Agent（Phase 2）

### 解决什么业务问题

月末要做暂估入库、委外加工费暂估、差异分摊、费用归集、凭证草稿。这些活规则明确但量大，且错一处要全表重算。

### 输入 / 输出

- **输入**：本期入库未开票明细、委外未结算明细、在制工单、费用单据、上期暂估与本期冲回、汇率。
- **输出**：暂估清单（按供应商/物料/期间）、冲回清单、差异分摊表、凭证草稿（借贷方 + 辅助核算项）、月结检查清单（哪些步骤完成、哪些卡住）。

### 写入哪些系统

| 系统 | 动作 | 等级 |
|---|---|---|
| 我们的对账账/执行账 | 写入暂估、冲回、分摊结果 | 自有对象 |
| ERP 财务 | 创建凭证**草稿**（不审核、不过账） | W1 |
| ERP | 创建暂估入库单草稿 | W1 |

**不写已过账凭证、不做期末结转、不碰税务申报。**

### 失败与回滚

- 借贷不平：拒绝生成凭证草稿，输出不平的差额与可能原因（漏单/税率/舍入）。
- 科目映射缺失（新物料无对应科目）：整批暂停，输出缺失映射清单。
- 与上期暂估不匹配（本期冲回金额 ≠ 上期暂估）：不平即报警，不自动调平。
- 回滚：草稿凭证可删除；已生成暂估单可红冲。

### 人工复核点

1. 所有凭证草稿必须由会计复核后手工过账。
2. 首次月结、会计政策变更月、审计期间，全程人工复核。
3. 差异分摊规则变更必须由财务负责人批准。

### 怎么衡量

月结天数（核心指标，CFO 最关心，报告 §4.1）；暂估准确率；月末返工次数。

## 1. 编排：Agent 之间怎么协作

单 Agent 解决单点，客户买的是"一件事办完"。两个主编排：

### 1.1 编排一：P2P 异常闭环（MVP 核心）

```
[A2 单据录入] 收货单/对账单进系统
      ↓
[A1 对账] 批次对账 → 发现差异（数量不符）
      ↓
[Supervisor] 判断差异类型 → 路由
      ├─ 缺单 → [A2] 补建收货单草稿 → 重新对账
      ├─ 报废未扣 → [A6] 生成委外损耗处置单
      └─ 单价不一致 → [A3] 拉历史价与协议价对比 → 出结论
      ↓
[A1 复算] 差异关闭 → 生成付款申请草稿
      ↓
[人工复核] 财务确认 → 提交（W1 → 人工升级为正式流程）
```

**Supervisor 的职责边界**：只做路由与状态维护，不做业务判断。业务判断永远在子 Agent，避免"总调度什么都懂一点、什么都不精"。

### 1.2 编排二：交付风险闭环（Phase 3）

```
[A4 齐套] 发现缺口 → 判断是否影响工单
      ↓
[A5 排程] 重排受影响工单，给出影响评估
      ↓
[A6 异常] 若无法通过重排解决 → 生成补料/外协/改期方案
      ↓
[A7 报价] 若涉及客户改期或加急 → 给出成本影响，供销售协商
```

### 1.3 编排的三条规则

1. **单向依赖**：下游 Agent 只能读上游结论，不能改上游结论；有异议走"重开批次"而不是篡改。
2. **状态唯一**：一个业务事务（如一个对账批次）在同一时刻只有一个 Supervisor 持有，避免并发写入冲突。
3. **失败不传染**：子 Agent 失败不阻塞其他分支，Supervisor 汇总"部分完成"并明示缺口。

---

## 2. 每个 Agent 都要回答的三个问题（评审必问）

1. **"这个 Agent 失败了会怎样？"** —— 必须能说出：失败被谁发现、多久发现、钱有没有动、单据有没有脏、谁负责收拾。
2. **"人为什么信它？"** —— 必须能点开任意一个结论，看到它读了哪几张单、哪几个字段、用了哪条规则、置信度多少。
3. **"不上它会损失什么？"** —— 必须能给出客户现有口径下的数字（工时、天数、差异金额、停线小时），而不是"提升效率"。

---

## 3. 评测与上线门槛

| 阶段 | 要求 |
|---|---|
| 离线评测 | 每个 Agent 一套金标准样本（≥ 200 条真实脱敏单据），准确率达标才进影子 |
| 影子运行 | 连续 2 个业务周期只出建议不写入，与人工结果比对，一致率 ≥ 90% |
| 灰度写入 | 从 W0 → W1 逐级放开，每次放开只对 1 家客户 1 个供应商/1 条产线 |
| 全量 | 连续 4 周无 P1 事故，且人工复核驳回率稳定低于 15% |

**熔断规则（全局）**：任一 Agent 在 1 小时内失败率 > 20%，自动降级为 W0（只建议不写），并通知运维；同客户同日触发 3 次熔断，整个租户进入只读模式。
