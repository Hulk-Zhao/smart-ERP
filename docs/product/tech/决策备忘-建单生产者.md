# 决策备忘：谁来建第一张工单

> 日期：2026-11-11 ｜ 决策人：产品负责人 ｜ 状态：待决 ｜ 决策时限：本次评审
> 一句话结论：**选 1（对账差异自动建单）**，这是本 POC 内唯一能把「工单 → 补偿队列 → 执行器」跑通的选项；2 和 3 在本 POC 内仍然演示不了。

## 为什么现在要决

- 工单持久化四段已全部合入 main（`7517b5d` → `c778687`）：API 的工单与审批记录已落库，`version` 对外「建单即 1」，写入口全部走事件 + 投影同事务，`rebuild_projection` 能还原。
- **但库里不会有新工单**：`POST /v1/tickets` 不存在，唯一建单入口是测试夹具。所以「持久化了」目前只对种子数据成立。
- 补偿执行器已交付（独立容器、倒序、租约、续约、`/metrics`），但**没有进程把工单写进 `compensation_task`**——生产者不在，执行器空转。
- 对外承诺层面：`07-商务口径与POC验收.md` 已经把「自动回滚/补偿」写成「本版不演示、不验收、不承诺」。

## 四问

### 1. 哪条能让链条在一个 POC 里演示完整？哪条仍然演示不了？

**只有 1 能。** 对账侧已有真实 `run` 与 `diff`，缺的只是收尾处建单；`uq_ticket_business` 保证一差异一单，重复触发不会多单。**2 不能**：运行时至今在生产代码里零构造，选它等于同时开「Agent 入口」和「建单」两个坑。**3 不能（本 POC 内）**：公网入口、签名校验、去重窗口、对方联调，任一未就绪就演示不了。三条都只解决「谁建单」，**都不同时解决「动作失败时谁写 `compensation_task`」**；要演示完整，必须同批做一个沙箱目标上的失败注入，否则链条断在第二处。

### 2. 每条的最小可交付是什么？最坏会拖多久？

**1**：一张「差异类型 → 场景 → 动作 spec」映射表，加一个在 `recon run` 收尾事务里建单的函数（幂等键 `recon:{run_id}:{diff_id}`）。最坏情况是映射表定不下来（差异类型与动作 spec 对不齐），演示顺延一个 POC 周期。
**2**：先在生产代码里真实构造 `runtime.execute()` 并跑通一个 Agent 入口，再挂 `agent:{run_id}:{step_no}` 建单。最坏情况是两个前置都从零起，本 POC 内无解，只能推到下一版本。
**3**：一个带签名校验与去重窗口的公网 webhook，加一个愿意联调的外部系统。最坏情况是安全评审或对方排期任一卡住，POC 直接没有这条演示——不是顺延，是取消。

### 3. 哪条会改变对外口径？

**1 要改。** 07 现在写「本版不演示、不验收、不承诺」；选 1 后应收窄为「生产默认不启用；POC 在沙箱目标上演示建单 → 失败 → 补偿 → 回滚」，内版 §4.2 / §5.5 / §6.2 与客户版同位置同步。
**2 不改**，仍无演示，原句继续成立。**3 不改**，仍无演示；但客户版要另加一句公网数据边界，因为多了一个外部入口。
**不选也不改主句**，但必须补工单来源（见第 4 问），否则「已持久化」会被读成「能建单」。

### 4. 如果不选，对外怎么写才不算误导？

可直接用这一句：「本期工单与审批记录来自导入/种子数据，用于验证持久化、版本号与投影还原；系统当前不提供业务建单入口。补偿执行器已交付，但没有生产者在运行，自动回滚不演示、不验收、不承诺。」
同时禁掉三句：「工单功能已上线」「支持自动建单」「写失败会自动回滚」。
只写「已持久化」而不写来源，读者会默认「能建单」，这就是误导。

## 推荐

**我推荐 1。** 它是唯一能在本 POC 内闭合链条的选项，幂等键与唯一约束已经把重复建单挡住，代价只是一张映射表。

**为什么不是 2**：运行时零构造，选它等于先造一个 Agent 入口，POC 内的未知数从 1 个变成 3 个。
**为什么不是 3**：公网入口 + 签名 + 重放策略是安全面扩张，还依赖外部方排期；演示风险不在我们手里。

**分情况**：如果你更在意「建单必须由外部系统触发」而不是「本 POC 内看到闭环」，那应该选 3，并把 POC 目标改成联调而非演示；如果你要的是内部 Agent 自动化，选 2，但本 POC 不承诺回滚演示。
