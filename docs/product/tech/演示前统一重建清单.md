# 演示前统一重建清单（只出文档，不执行）

> 适用：POC 演示前一天/当天由**集成会话**统一执行一次重建。**本文件先于执行存在**；执行前需用户明确授权。
> 现状基线：live 八容器镜像均为 `smart-erp/app:12ba3e3`，**当前处于冻结状态：不得重灌、不得重启、不得写入**。

## 1. 什么时候才重建

- 演示栈必须与 `main` 上含当晚修复的 commit 一致（当前 `main = e8b5392`，高于演示栈钉的 `12ba3e3`）。
- 只在**用户明确说「执行重建」**后动手；不要因为「代码又合了一个 PR」就自动重灌。

## 2. 重建到哪个 commit

- 目标 = 重建时刻的 `origin/main` sha，**执行前记录并写进 `deploy/smart-erp/RELEASES.md`**。
- 镜像 tag 与 sha 对齐（例如 `smart-erp/app:<sha7>`）；不得用 `latest` 或不带 tag 的镜像。
- 若当天还有未合入的修复，**先合再重建**；不得在演示栈上手改代码或挂载本地文件。

## 3. 重建顺序（严格按序）

1. **冻结窗口确认**：无 PR 正在合并、无流在写共享树；记录当前 live 镜像 tag 作为回滚点。
2. **构建**（不是只拉镜像）：`docker compose -f deploy/smart-erp/docker-compose.yml build`。
3. **api + web 同步重建**：本次含**破坏性字段改名**（`required_roles`/`missing_roles` → `approval_*` / `execution_*`），**只换一边前端读不到字段、页面会空**，必须同一批 `up -d`。
4. **`up -d`**：等 8 个容器全部 `healthy`；不健康先看日志，不要带病继续。
5. **复位四步**（顺序不可换）：
   1. `python scripts/load.py --all`（重灌种子）
   2. `docker restart erp_api`（**必须**：清 API 进程内幂等缓存；不做这步固定 `idem_key` 会命中旧缓存 → 409）
   3. `POST /stub/reset`（桩复位；首个单号应为 `PO-STUB-000001`）
   4. 四身份自检（发起人 / 审批人 / 复核人 / 观察者各跑一次最小动作）
6. **验收记录**：把镜像 tag、四步输出、验证点结果写进 `RELEASES.md`，**当轮写，不事后补**。

## 4. 重建后必须看到的验证点

| # | 验证点 | 期望 |
|---|---|---|
| 1 | 8 容器状态 | 全部 `healthy`（含 `connector-gw`、`doc`） |
| 2 | `GET /healthz`（api / doc / gw） | 200 |
| 3 | `POST /stub/reset` 后首单 | `PO-STUB-000001`（连续两次 reset 均如此） |
| 4 | 四身份自检 | 全部通过；403 时 `detail` 原文可见（如「角色 [reviewer] 不能复核 finance 类场景」） |
| 5 | 写路径一张单 | 四道闸 → 审批 → 执行 → 审计链 `ok/head_hash` 一致，回执含 `executed_steps` |
| 6 | 工单详情 | 渲染 `executed_steps`（序号 / action_key / 状态 / 写等级 / system·object / idem_key） |
| 7 | 对账 | 跑出**非种子批次**；`diff_rate` 不为单侧伪结果 |
| 8 | 审批字段 | 审批页与工单页都显示 `approval_*` / `execution_*` 两组（证明 api+web 同版本） |
| 9 | `connector-gw` 路由 | 仅 `/healthz`、`/readyz`（GET/HEAD），不得声称已启用连接器沙箱 |

## 5. 红线

1. **当天不再重建**：演示日只允许只读检查与业务操作，不再 `build` / `up -d` / `load.py` / `restart`。
2. **不得只重启单个服务当作重建**：`docker restart` 不清镜像版本，改没改代码无法证明。
3. **不得重灌种子后跳过 `docker restart erp_api`**：幂等缓存是进程内的，跳过必出 409。
4. **不得用 live 栈做性能测试或压测**：性能数字只在独立环境采集，且按分阶段口径报。
5. **不得在演示栈上手改配置/挂载文件**；所有差异必须回到 main 与 compose。
6. 重建失败：按记录的上一镜像 tag 回滚 `up -d`，**不要现场调试**，把日志带回会后处理。

## 6. 与文档口径的关系

- 对外性能话术固定为：「性能以 POC 环境实测为准；已在 16C/32T 工作站完成合成数据基线，目标规格尚未验证」。重建不改变这条。
- 文件通道当前**未接线、不可用**（`statement_files` 只会 `DATA_MISSING`）；演示脚本不得声称「已支持供应商对账单文件导入」。
