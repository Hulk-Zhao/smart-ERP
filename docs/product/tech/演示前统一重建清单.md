# 演示前统一重建清单（只出文档，不执行）

> 适用：POC 演示前一天/当天由**集成会话**统一执行一次重建。**本文件先于执行存在**；执行前需用户明确授权。
> 现状基线：live 八容器镜像均为 `smart-erp/app:12ba3e3`，**当前处于冻结状态：不得重灌、不得重启、不得写入**。

## 1. 什么时候才重建

- 演示栈必须与 `main` 上含当晚修复的 commit 一致（截至 2026-11-11，`main = 8416788`，高于演示栈钉的 `12ba3e3`）。
- 数量事实（`12ba3e3 → 8416788`）：**9 个提交、65 个文件、`+20751/−140`**；其中 **迁移 +1（`0014_connector_idem_grants`，head 从 `0013` 变 `0014`）**，**审计链零改动**（该区间 `apps/audit/` 无 diff）。
- 只在**用户明确说「执行重建」**后动手；不要因为「代码又合了一个 PR」就自动重灌。

## 2. 重建到哪个 commit

- 目标 = 重建时刻的 `origin/main` sha，**执行前记录并写进 `deploy/smart-erp/RELEASES.md`**。
- 当前目标为 `8416788`（`#145`–`#152` 与 `#157` 的合并结果）；重建到该 sha 时，库必须先升到 `0014`。
- **`#158` 合入后目标会再前移**：它是破坏性字段改名（`required_roles`/`missing_roles` → `approval_required_roles`/`execution_required_roles` 等），届时 api + web 必须再同步重建一次。
- 镜像 tag 与 sha 对齐（例如 `smart-erp/app:<sha7>`）；不得用 `latest` 或不带 tag 的镜像。
- 若当天还有未合入的修复，**先合再重建**；不得在演示栈上手改代码或挂载本地文件。

## 3. 重建顺序（严格按序）

1. **冻结窗口确认**：无 PR 正在合并、无流在写共享树；记录当前 live 镜像 tag 作为回滚点。
2. **构建**（不是只拉镜像）：`docker compose -f deploy/smart-erp/docker-compose.yml build`。
3. **迁移先行**：对目标库执行 `alembic upgrade head`，确认 `alembic current` = `0014_connector_idem_grants`。**重建前必须跑 `0014`**，不得跳过（`0014` 只授 `erp_app` 的 SELECT/INSERT/UPDATE、撤 DELETE/TRUNCATE，无表结构变更，但不跑会让连接器幂等落库失败）。
4. **api + web 同步重建**：`8416788` 本次**不含**破坏性字段改名，但 api 与 web 仍必须同批构建、同批 `up -d`——只换一边会出现前后端字段/渲染错配（`12ba3e3` 的后端配 `5b2c0dc` 的前端即为反例）。**`#158` 合入后**另需再同步一次（见 §5 红线 7）。
5. **`up -d`**：等 8 个容器全部 `healthy`；不健康先看日志，不要带病继续。
6. **复位四步**（顺序不可换）：
   1. `python scripts/load.py --all`（重灌种子）
   2. `docker restart erp_api`（**必须**：清 API 进程内幂等缓存；不做这步固定 `idem_key` 会命中旧缓存 → 409）
   3. `POST /stub/reset`（桩复位；首个单号应为 `PO-STUB-000001`）
   4. 四身份自检（发起人 / 审批人 / 复核人 / 观察者各跑一次最小动作）
7. **验收记录**：把镜像 tag、四步输出、验证点结果写进 `RELEASES.md`，**当轮写，不事后补**。

## 5. 红线

1. **当天不再重建**：演示日只允许只读检查与业务操作，不再 `build` / `up -d` / `load.py` / `restart`。
2. **不得只重启单个服务当作重建**：`docker restart` 不清镜像版本，改没改代码无法证明。
3. **不得重灌种子后跳过 `docker restart erp_api`**：幂等缓存是进程内的，跳过必出 409。
4. **不得用 live 栈做性能测试或压测**：性能数字只在独立环境采集，且按分阶段口径报。
5. **不得在演示栈上手改配置/挂载文件**；所有差异必须回到 main 与 compose。
6. 重建失败：按记录的上一镜像 tag 回滚 `up -d`，**不要现场调试**，把日志带回会后处理。
7. **`#158` 合入后必须再做一次 api + web 同步重建**：它是破坏性字段改名，旧前端读不到 `approval_required_roles` 等新字段、新后端也不再返回旧名；不得让 `#158` 悄悄合入后直接演示，否则现场白屏。
