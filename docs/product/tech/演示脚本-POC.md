# POC 演示脚本（可照着念）

> 版本：v1.1-draft（2026-11-11）｜适用：销售 / 售前在客户现场，或远程共享屏幕
> 入口：`http://localhost:8088/`｜前提：演示栈已起、五容器 healthy、三套演示数据已灌。
> 第 8 段写路径另需：本机启动模拟外部系统 `python -m apps.connectors.u8.stub_server --host 127.0.0.1 --port 8013`，并让 API 指向它 `ERP_U8_BASE_URL=http://127.0.0.1:8013`；要演示补偿还需 `ERP_ROLLBACK_SYNC_ENABLED=1`（默认关闭）。
> 核对方式：第 1–7 段在本机演示栈上逐步点击核对页面文案与数字（工作台、工单详情 `/tickets/38e403ec-4b51-55f7-b88a-1ec198f32a9e`、审批、对账批次 `316d16a4-c0b1-595f-ad5e-4b8a664d2997`、计量表）；第 8 段按分支 `feat/s1-demo-write-path @ 455c0ed` 的代码与桩接口核对，**该段口径待 S4 复核后才定稿**。**页面数字会随操作变化**，脚本里的数字是核对时的实际值，讲的时候说「当前演示数据是……」。
> 一句话定调：**这是一条跑在本地模拟外部系统上的决策闭环演示——外部系统是我们自带的模拟桩，不是真实 U8，也不是客户的系统；这不是生产上线演示。**

## 0. 开场（40 秒，照念）

> 「今天看三件事：第一，一张有资金风险的工单怎么被人决策；第二，决策留下什么证据、能不能验；第三，对账结果怎么变成可核对的计费行。
> 先讲清范围，四句。一，**我们的『外部系统』是本地模拟桩**（u8-stub），不是你们的 U8，也不是任何真实 ERP——它启动有横幅、每个响应带 `X-Simulated-System: u8-stub` 头、响应体里写着 `simulated: true`，一会儿我打开终端让你们自己查；二，对你们的系统本期是零写入，不写 ERP、不碰资金、不产生凭证；三，工单来自演示数据导入，系统当前不提供业务建单入口；四，告警只到告警管理组件，不接通知渠道；**失败后自动进补偿队列这条还没有生产者，本版不演示**，能演示的是在模拟桩上手动触发一次补偿（删除草稿）。」

**不要做的事**：第 3 段那张 73.5 万的既有工单不要点「通过」；只有第 8 段专门准备的演示单 `DEMO-W2-WRITE-9001` 允许点「通过」，因为它的写入目标是本机模拟桩。除第 8 段外，任何「通过」都不要点。

## 1. 工作台：今天要人决定什么（约 60 秒）

**点什么**：打开 `http://localhost:8088/`，停在「工作台」（左上导航第一项；页面标题「今日指挥台」）。

**会看到**（核对时的实际值；两个数字各有两个时点，见下）：
- 四张卡：`待你决策 4`（种子起手；第 8 段批掉 `DEMO-W2-WRITE-9001` 后为 **3**）、`涉及资金 735,000.00`、`W3 禁止自动执行`、`执行中 / 校验中 2`（种子态 1+1；第 8 段后为 **3** = 2+1）
- 区块：`待你决策`、`风险雷达`、`对账摘要`、`状态分布`、`最近工单`
- 页头摘要：`待审批 4 当前页工单 16`（第 8 段后 `待审批 3`）
- 按钮：`发起对账`

**照念**：
> 「待你决策 4 张，涉及资金 73 万 5 千。数字不是前端估的，是审批队列接口返回的；这里的『W3』是禁止自动执行的等级，后面会看到它怎么拦人。」

（这句只在开场成立：第 8 段把写路径演示单批掉后，工作台回到 `待你决策 3`、`执行中 / 校验中 3`。观众两次对照时按「开场 4、写路径后 3」交代，不要说成前后矛盾。）

**想让客户理解**：系统先把「需要人拍板」的事排到最前面，且资金敞口一眼可见。

**如果不对怎么办**：
- 数字是 0 或出现「没有身份可查」：先看右上角身份/角色是否选好，刷新一次；仍为 0 就点「工单」，用 16 条样本继续，**工作台可整段跳过**，不影响后面任何一步。
- 页面报 401：说明演示令牌没带上或过期，让运维重启前端容器或重新注入演示身份；401 时不要继续点，直接跳到第 2 步用直链。

## 3. 审批决策：双人复核与角色（约 60 秒）

**点什么**：导航「审批」。页头有 `双人复核`。找到金额 `735,000.00`、状态 `待审批` 的那张（核对时 URL 带 `?ticket=73279530-d9e6-5ac0-a765-003dff1177f4`）。

**会看到**：
- `待办列表`，每条带 `涉及资金` 标签
- 右侧/下方有角色选择「`以该角色提交`」
- 审批意见输入框：`审批意见（驳回必填；意见仅你本人可见正文）`
- 两个按钮：`驳回`、`通过`；快捷键 `A 通过`、`R 驳回`

**照念**：
> 「决策要人做，而且要双人复核。这里可以看到当前身份能批哪一步；意见只有审批人本人看得到正文，发起人看不到。这张 73.5 万的单子我今天不点通过——但第 8 段我会换一张专门的演示单真的点通过，那笔写入只落在模拟桩上。」

**若被问「到底几个人签」**：照实说两处口径——审批阶段返回 `required_roles=["approver"]`（一票），执行动作返回 `["approver","reviewer"]`（执行前还有一道双签闸）。两者目前不一致，已登记为待统一项；**不替产品判定哪个对**，也不据此承诺「跨类别分权」。

**点一下（可选，安全）**：点 `驳回`，不填意见，按钮应保持不可提交；填一句意见后可提交。**这张不要点通过**（要演示写路径请走第 8 段）。

**想让客户理解**：审批不是橡皮图章，有角色约束、有必填意见、有留痕。

**如果不对怎么办**：
- 点「通过」报错或缺角色：正常，说明角色闸生效；顺势讲「缺角色」而不是道歉。
- 待办列表为空：切到「全部」筛选；仍为空就用第 2 步的工单直链讲「审批进度」，**审批提交动作可跳过**。
- 401/403：让运维确认演示身份；不要现场改配置。403 时只讲按钮和规则，不提交。

## 5. AI 建议：两种情形都要讲清（约 60 秒）

**点什么**：在工单详情页看右侧「助手」面板（桌面默认展开；收起后点右上 `助手` 重新打开）。面板标题 `助手`，区块 `下一步`，右侧小字 `后端建议接口`。

**情形 A：有模型**
- 徽标显示 `模型建议`，下方有「生成于 …」
- **照念**：
  > 「这是模型给的建议。注意它只是建议：不写库、不执行动作，最终点按钮的还是人。系统不会替客户做决定。」

**情形 B：无模型 / 模型超时**
- 徽标显示 `规则建议（模型未参与）`，并显示 `降级原因：…`
- **照念**：
  > 「这次模型没有参与，页面明确标了『规则建议（模型未参与）』，下面写了降级原因。我们不把规则结果说成 AI 结论——客户看到什么，就是系统实际用了什么。」

**还没有打开工单时**：面板会显示「打开一张工单详情，助手会调用 `/v1/assistant/suggest` 生成下一步建议。本页不再用规则拼建议。」——这正好证明它是按工单上下文取建议，不是页面上随便拼的。

**如果不对怎么办**：
- 面板没出来：点右上 `助手`；窄屏下默认收起是设计如此，不是故障。
- 显示「请求超时」而不是降级：这是前端等待超时，后端降级路径没回来；刷新一次，仍超时就按「无模型」讲，不要硬说是模型建议。
- 两种情形都无法触发：直接讲「有模型显示模型建议，无模型显示规则建议并标注」，**这一步可跳过**，不影响闭环。

## 6. 对账批次与差异（约 70 秒）

**点什么**：导航「对账」→ 打开最近批次（核对时 `/recon/316d16a4-c0b1-595f-ad5e-4b8a664d2997`）。

**会看到**（实际值）：
- 状态 `待人工复核`
- `指标`：`供应商行 104`、`匹配行 32`、`差异行 80`、`差异金额 7,108,301.10`；另有权重 `模糊/多候选`、`仅候选`、`未匹配`、`自动处置`
- `差异列表`，列含 `类型`，提示「点击行查看字段级 diff 与证据坐标」

**照念**：
> 「104 条供应商行，32 条自动匹配，80 条差异、差异金额 710 万。批次结论没定，所以状态是待人工复核——注意，这不等于整个批次不能计费，已自动匹配的行照计，后面计量表会看到。」

**这一段必须先声明数据从哪来（照念，不能省）**：
> 「先说清这批数据的来源：**输入是我们当场提供的 JSON，不是从你们的供应商系统拉下来的**，也不是文件通道或邮件自动读进来的。但请把两件事分开看——**引擎、落库、差异计算、审计是真的；输入数据是当场提供的**。」

| 是真的 | 是当场提供/暂缺的 |
|---|---|
| 对账引擎真的在算：匹配、归因、差异金额都按真实规则产出 | 输入数据：请求内联的 `dataset`（对账页的 JSON 输入框），不是从任何外部系统取的 |
| 结果真的落库：批次、行、差异、证据坐标都可再查 | 文件通道：要新写 CSV→对账行映射，且 `our_lines` 仍无来源，本期不做 |
| 差异逐行带证据、审计影像可核 | 单据解析（docparse）：无 `main`、无路由，需要新写适配，本期不做 |
| 批次状态与计量表由真实数据推导 | 演示数据规模只覆盖本次演示所需行，不代表客户数据规模 |

**现场跑一次（可选，约 30 秒；503 已修复，可直接跑）**：在「对账」页的 JSON 输入框粘一段 `dataset` → 提交 → 会生成**新的批次号**，状态、指标、差异列表都是这次现算的；点进差异仍能看到字段级 diff 与证据。

> 「这个批次号是刚刚生成的，不是预置的；数字也是刚算出来的。但输入还是我贴进去的 JSON——系统目前没有接你们的供应商系统，也没有解析文件或邮件的通道。」

**两条边界（讲的时候必须带上）**：
- 修复前 `POST /v1/recon/runs` 恒返回 503（`E-CONN-UNAVAILABLE`、`stage=input`）：原因是 API 进程从未装配连接器、取不到 `pick_meta` 的元数据，**不是数据缺失**。该问题已在 #130 修复并合入 main `995c344`（S2 已实测：内联 `dataset` 提交返回 201），**现在可以现场跑**；若现场仍报 503，说明演示栈不是含该修复的版本，跳过现场跑、只讲已有批次（§6 开头那条直链），不要现场改配置或造数据。
- 文件通道与 docparse 都属于功能开发，不在本期；因此「接了系统自动对账」这句话本期不成立。

**点一条差异（可选，30 秒）**：进入差异详情，会看到 `字段级差异`、`置信度`、`证据 N 条`、`处置草稿`（含 `建议`）、`证据下钻`、`判断提示`（「草稿是建议，不是执行结果」）。

**想让客户理解**：差异是逐行有证据的，处置草稿不是自动执行。

**如果不对怎么办**：
- 批次列表为空：用直链；直链也空说明数据被重置，**对账一段可跳过**，直接讲计量口径（用第 7 步的数字需要批次存在，若不存在就只讲「计费行 = 自动匹配行 − 两类减项」）。
- 数字与脚本不一致：以页面为准，别念旧数字；脚本数字只用于「事先知道该看哪几项」。
- 差异行点不开：讲列表层面的类型与金额即可，**差异详情可跳过**。
- 现场跑对账报 503 `E-CONN-UNAVAILABLE`（`stage=input`）：说明演示栈不是含 #130（main `995c344`）的版本，**不要现场改配置或造数据**，跳过现场跑，只讲已有批次。

## 7. 计量账本：口径与上界（约 80 秒）

**点什么**：在批次页点 `计量表 →`（或直链 `/recon/316d16a4-c0b1-595f-ad5e-4b8a664d2997/metering`）。

**会看到**（实际值）：
- `本期金额 25.60 CNY`、`累计金额`、`封顶余额`
- `单价 0.80 CNY`，来源可展开
- `四类行`：`供应商对账单行数（应处理）104`、`有效对账行数 32`、`计费行数（billable 桶）32`、`本次明细行数`
- 明确提示：`计费行数（billable 桶）是上界，不是精确值`
- 批次未定提示：`该批次结论未定（conclusive=false），本计量表仅反映当前程序性事实。`
- `算式`、`CSV 导出与完整性`，按钮 `下载 CSV`

**照念**：
> 「计费单元是有效对账行，32 行；本期没有两类减项回填，所以计费行数也是 32，单价 0.80，本期 25.60。页面自己写了『这是上界，不是精确值』——我们不在客户面前把它说成精确账单。批次结论未定也照计已匹配的行，这是合同口径：计费不以批次放行为前提。」

**两条必须提前知道的页面事实**：
1. `算式` 区有服务端原文可能把计费行数写作「有效对账行数」；**以页面顶部「四类行」为准**，现场按本脚本口径解释，不要跟着原文说错。
2. 本期 `已确认错放行`、`客户原因` 无数据源，按 0 扣减；所以两个数相等，不是巧合。

**如果不对怎么办**：
- 计量页 503 或无单价：说明单价未配置。**不要现场改环境变量**；改用已验证批次；仍不行就只讲四类行与上界口径，**金额这一屏跳过**。
- 本期金额与「行数 × 单价」对不上：先看是否有封顶或累计；解释不清就只报页面原值，不现场算。
- `下载 CSV` 失败：不影响演示，讲「逐行明细可导出」即可。

## 8. 写路径：审批后写入本地模拟外部系统（约 70 秒，可选）

**这一段最前面必须先声明（照念，不能省）**：

> 「接下来是全篇唯一一次真的发出外部 HTTP 请求。请先看清楚对面是谁：**不是你们的 U8，也不是任何真实 ERP，而是我们仓库里自带的一个模拟桩（u8-stub）**，只监听本机 `127.0.0.1:8013`，不连外网。它有三重标注——启动时终端打印横幅、每个响应带 `X-Simulated-System: u8-stub` 响应头、响应体里有 `simulated: true`。所以这段证明的是『连接器真的会发请求、会回查、会删草稿』，**不是**『我们已经接上真实 U8』。」

**点什么**：

1. 导航「审批」，找 `DEMO-W2-WRITE-9001`（委外加工费差异，B 级连接器）。页面要求双人复核：先以**发起人身份**提交，再以**审批人身份**（须与发起人不同）提交，不要跳角色。
2. **审批人身份**点 `通过`。若因身份或权限原因被拒绝，如实说明原因，**不要现场改配置或换账号**。通过后工单进入 `执行中`，`执行步骤` 里出现这条写入；工作台随之变为 `待你决策 3`、`执行中 / 校验中 3`。
3. 打开该工单详情，滚到 `可执行动作`，能看到 `触发补偿 / 回滚`（只有 `执行中` / `补偿中` 才有；若 `rollback_available=false`，按钮是灰的，说明同步回滚开关没开）。

**现场自证（这一段的关键：让客户自己查，不要只由我们说）**：

```bash
curl http://127.0.0.1:8013/stub/requests   # 桩收到的全部请求：预演 → POST 建草稿 → 回查
curl http://127.0.0.1:8013/stub/receipts   # 已落下的草稿：U8 单号 cCode、received_at、关键字段回显
```

> 「这两个地址是**桩自己的账本**，不是我们的数据库。请求记在 `requests` 里，单据在 `receipts` 里——刚才那一下到底出没出去、落没落下，您现在就能看到，不用信我说。」

（Windows PowerShell：用 `curl.exe`；环境变量写 `$env:ERP_U8_BASE_URL="http://127.0.0.1:8013"`。）

**单号说明（不要写死）**：`POST /stub/reset` **不重置桩进程内序号**，所以每次跑出来的草稿单号会变（本次重灌后实测是 `PO-STUB-000002`）。口播和截图不要写死单号：要么说「以现场回执为准」，要么只引用稳定的 `source_doc_no=PO-STUB-DEMO-W2-WRITE-9001`。

**补偿（可选，约 30 秒）**：工单还在 `执行中` 时，点 `触发补偿 / 回滚`，选一个失败分类（`fail_code`）、勾选确认、写理由后提交。补偿动作是**删除草稿**（`u8.po.delete_draft` / `u8.arrival.delete_draft`），不是反做一张红冲单。提交后再查一次：

```bash
curl http://127.0.0.1:8013/stub/reversals  # 出现该 U8 单号的冲销记录
curl http://127.0.0.1:8013/stub/receipts   # 该单号已从草稿里消失
```

> 「草稿删掉了，桩这边也能查到冲销记录。但请注意：**这次冲销没有写入 `ticket_event`，审计链上查不到这一步，这是下一步要补的缺口**。所以这里能验的是『草稿确实被删了』，不是『回滚已经可审计』。」

**必须同时说明的两件事（保守口径，不许省）**：

- 这条同步补偿入口**默认是关闭的**（`ERP_ROLLBACK_SYNC_ENABLED` 未设置时为 false，接口返回 `E-ROLLBACK-UNAVAILABLE`）；演示前打开，是为了演示，不代表线上默认开放。
- 这条同步路径**不写 `ticket_event`、没有租约与重试**（代码注释里写明了）。所以它是「能在桩上演示的手动补偿」，**不是**「完整可审计的自动补偿」。失败后自动进补偿队列那条链路**没有生产者，本版不演示**。

**W3 对照（约 40 秒，和写路径成对讲）**：

> 「再看一张 W3 的资金单 `DEMO-W3-FUND-9002`。它在 **AccessGate 就被拒**，错误码 `E-POLICY-W3FORBIDDEN`，**在换令牌之前**就停住——连接器根本没被调用。」

现场自证：先 `curl /stub/requests` 记下当前条数，再对该 W3 工单提交审批，然后再 `curl /stub/requests` 一次，**条数不变**。

> 「`requests` 一条没多，这就是『零外部写入』的实证，不是我口头保证。W3 是在访问校验那一步、**换令牌之前**就被拒的，连接器根本没被调用。」

**这一段的边界（讲的时候必须带上）**：

- 有写实现的**只有 U8 制单（草稿）这一类**；WMS 没有连接器、没有写实现，文件通道只读。**所以没有「多系统写入」这回事**，不要用这个词。
- 桩只监听 `127.0.0.1`，不是任何客户的系统；演示数据是种子数据，不是客户数据。

**如果不对怎么办**：

- `/stub/requests` 一直为空、审批时报连接失败：API 没设 `ERP_U8_BASE_URL` 或桩没起。**不要现场改成假成功**——不设置时写入会显式失败，不会静默成功，这本身也是可以讲的点。仍不行就跳过整段。
- 工单没有待审批的写入动作：种子数据被重置，跳过本段，不要现场造单。
- 补偿按钮是灰的 / 报 `E-ROLLBACK-UNAVAILABLE`：开关没开（默认关），说明这是默认安全态，**不要现场改配置**。
- 补偿报状态非法：工单不在 `执行中` / `补偿中`（例如已经回滚过），换一张或跳过。
- `receipts` 里有单据但 `reversals` 没多：补偿没真正发出去，如实说「这一步今天没走通」，不要用截图或口头替代。

## 9. 收尾（约 30 秒，照念）

> 「三句话收尾：第一，决策是人做的，系统只排优先级、给建议、留证据；第二，证据能验——字段级差异、哈希链、锚点，写路径的请求和回执也能在桩上当场查；第三，计费按有效对账行，本期是上界，不是精确账单。
> 不承诺的部分也明确：本期不接告警通知、不演示失败后自动补偿、不给任何性能秒数、没有接你们的真实 U8 或 WMS、不是生产上线。这些等 POC 在你们数据上跑完再谈。」

## 11. 现场禁区（说了就要能兑现）

| 不能说 | 为什么不能说 |
|---|---|
| 「已接真实 U8 / 已对接客户的 ERP」 | 写路径的对端是仓库自带模拟桩（启动横幅 + `X-Simulated-System: u8-stub` 头 + `simulated: true`）；没有任何真实 U8 或客户系统参与。 |
| 「多系统写入（U8 和 WMS 一起写）」 | 只有 U8 制单（草稿）有写实现；WMS 没有连接器、没有写实现，文件通道只读。 |
| 「按业务类别分权复核 / 跨类别不能审」 | 当前审批 API 路径未把 `scene_code` 传进审批构建，`BusinessCategoryPolicy` 在 `scene_code=None` 时直接 return，类别闸实际不生效；属已知缺陷，卡 `B-APPROVAL-CATEGORY-BYPASS` 修复中。本期审批只有角色与双人复核。客户问时答：「本期审批按角色与双人复核；业务类别分级复核是下一步。」 |
| 「桩单号固定是 `PO-STUB-000001` / 写死截图上的单号」 | `POST /stub/reset` 不重置桩进程内序号，单号会递增（本次重灌后实测 `PO-STUB-000002`） | 「单号以现场回执为准；稳定的是 `source_doc_no=PO-STUB-DEMO-W2-WRITE-9001`。」 |
| 「已经接了供应商系统 / 文件通道 / 邮件，自动拉数对账」 | 本期唯一可行输入是**请求内联 `dataset`**（对账页 JSON 输入框），数据当场提供；文件通道要新写 CSV→对账行映射且 `our_lines` 无来源，docparse 无 `main`、无路由，二者都属功能开发 | 「对账是现场给数据算的，输入由我们提供；系统不读取贵司系统，也不回传。」 |
| 「写进去的是真实业务单据」 | 落的是模拟桩内存里的草稿，桩重启即清空；不产生任何真实凭证、付款或账务影响。 |
| 「写失败会自动回滚 / 自动补偿可用」 | 自动补偿没有生产者，本版不演示；能演示的只是模拟桩上的手动补偿（删除草稿），且同步入口默认关闭、不写 `ticket_event`。 |
| **反向禁区**：「桩上能查到冲销，所以回滚可审计」 | 冲销记录只在桩的 `/stub/reversals` 里，**没有写入 `ticket_event`，审计链上查不到这一步**。能验的是「草稿被删掉了」，不是「回滚闭环可审计」。这是已知缺口，不是已完成能力。 |
| 「实时告警通知 / 有人 7×24 值班 / 告警会打电话」 | 本期不接外部通知渠道，Alertmanager 的 receiver 为空，告警只停在 Alertmanager，没有人被叫醒。 |
| 「AI 自动决策 / AI 直接处理」 | 只出建议，不写库、不执行动作；决策由人做。模型不可用时还是规则建议，不能叫 AI 建议。 |
| 「10 万行只要 X 秒」 | S7 对账实测基线尚未产出；任何秒数都会在现场被当成承诺。只能说「以 POC 在你们环境实测为准」。 |
| 「灾备已就绪 / 双活 / 可切换」 | 没有故障切换演练与 RTO/RPO 证据，说了无法兑现。 |
| 「云端已经上线 / 生产可用」 | 当前是本机演示栈，不是生产部署；上线需要发布门禁与运维交接。 |
| 「审计不可篡改，绝对合规」 | 链可验只证明记录连续；不要扩展成合规认证结论。 |
| 「准确率 100% / 95%」 | 真实数据准确率尚未在客户数据上测量，没有任何可引用分子分母。 |

**遇到客户追问时的标准句**：
> 「这项能力目前不在本版演示范围，我不能用演示数据替它背书；POC 跑完我们按实测结果给书面结论。」

## 12. 演示前 5 分钟检查

0. **重灌种子后必须重启 API（硬前置）**：执行 `demo/load.py --all` 后先 `docker restart erp_api`，再打开页面。原因：种子把 `pending_write.idem_key` 固定，而写结果缓存在 API 进程内存（`erp.connector_idempotency` 表为空）；只重灌库、不重启进程，写路径会被判为 replay、不发 POST，桩若已 `reset` 就查不到请求 → `409 E-VERIFY-MISMATCH (F6)`，而且那次是零写入失败，台上很难解释。
1. 打开 `http://localhost:8088/`，确认工作台不是 401、不是空白；`待你决策` 不是 0（种子态应为 4）。
2. 预开三个标签页：工作台、`/tickets/38e403ec-4b51-55f7-b88a-1ec198f32a9e`、`/recon/316d16a4-c0b1-595f-ad5e-4b8a664d2997/metering`。
3. 确认右侧「助手」面板能展开；先看一眼当前是 `模型建议` 还是 `规则建议（模型未参与）`，决定现场讲 A 还是 B。
4. 要演示第 8 段时，另开终端：确认桩已起（能看到启动横幅）、`curl http://127.0.0.1:8013/stub/healthz` 正常、`POST /stub/reset` 清一次历史（可选，清完 `requests` 计数从 0 起；**reset 不重置桩进程内序号，单号可能不是 `000001`，以现场回执为准**）、记下 `/stub/requests` 当前条数（W3 对照要用）；确认 `DEMO-W2-WRITE-9001` 还在 `待审批`；并确认演示侧具备**发起人身份**与**审批人身份**（两者不同）。业务类别分级复核当前未生效，不作为演示前置条件。
5. 要演示补偿时，确认 `ERP_ROLLBACK_SYNC_ENABLED=1`（否则工单页补偿按钮是灰的），并确认该工单处于 `执行中`。
6. **除 `DEMO-W2-WRITE-9001` 外不要点「通过」**；其余决策演示用「驳回」并写一句意见。
7. 记下页面当前数字（工作台 `待你决策 4`（第 8 段后 3）/ `执行中 / 校验中 2`（第 8 段后 3）/ 735,000.00；工单 640,000.00；批次 104/32/80/7,108,301.10；计量 32 行 / 0.80 / 25.60），现场以页面为准。

## 13. 明确不演示的步骤（照实说明，不假设存在）

- **新建工单**：本版没有 `POST /v1/tickets`，工单只能看、不能建；演示从已有数据开始。客户问「怎么建单」时答：「本期工单来自导入/种子数据，业务建单入口不在本版范围。」
- **失败后自动进补偿队列**：自动补偿仍没有生产者把工单写入补偿队列；不要点、不要假装点了。**可以在模拟桩上手动补偿**（第 8 段），但不要说成「自动回滚」。
- **写入真实 U8 / WMS**：WMS 没有连接器与写实现，文件通道只读；U8 写入只指向本机模拟桩。不要说「多系统写入」。
- **从供应商系统 / 文件 / 邮件自动取数对账**：本期只支持请求内联 `dataset`（对账页 JSON 输入框），数据当场提供；文件通道与 docparse 未适配，属功能开发。不要说「接了系统自动对账」。
- **现场发告警**：可以看指标与规则，但不接通知渠道；不要演示「发一条告警到手机」。
- **现场跑 10 万行对账**：没有 S7 实测基线，现场跑会把演示变成性能承诺；用已有批次讲口径即可。
