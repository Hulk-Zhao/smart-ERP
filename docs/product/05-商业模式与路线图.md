## 1. 定价：正面回应"按动作计费不可预测"

### 1.1 先把问题说清楚

报告指出三种计费方式的现状（§4.4）：

| 方式 | 现状 | 客户感受 |
|---|---|---|
| 按席位 | 正在失效——一个 Agent 替 20 个人干活，"用的人"和"付钱的人"分离 | "我该买几个席位？" |
| 按动作（AI Unit / Credits） | 新共识但体验差：SAP 0.02 AI Unit/动作、Microsoft Agent 动作 5 分、NetSuite AI Units | "账单不可预测，CFO 无法编预算" |
| 按结果 | 有空间但难落地，需对"结果"定义与测量口径达成一致 | "怎么算我的收益？" |

我们的答案不是"按结果计费"这一句口号，而是**三段式结构**：固定可预测的底座 + 有上限的结果费 + 一次性的诊断与上线。核心承诺是**客户在签约时就能算出全年最大支出**。

### 1.2 价格结构

```
年度合同额 = 平台订阅（固定，占比 50–60%）
           + 结果费（浮动，有硬封顶，占比 20–40%）
           + 一次性（诊断 + 上线，首年发生）

硬约束：结果费 ≤ 平台订阅 × 3（年度封顶，写进合同）
      不按席位、不按动作、不参与客户与原厂的 ERP 许可分成
```

#### （1）平台订阅：按"连接器 × 组织"，不按人头

| 项 | 假设价格 | 说明 |
|---|---|---|
| 基础包 | ¥120,000 / 年 | 含 3 个连接器、1 个组织、Agent 工单与审计、全部界面 |
| 追加连接器 | ¥20,000 / 年 / 个 | 连接器是成本也是价值锚点（每多连一个系统，跨系统价值多一层） |
| 追加组织（工厂/法人） | ¥40,000 / 年 / 个 | 多工厂客户的主要增量 |
| 私有化部署许可 | 订阅 × 1.5 + 一次性部署 ¥300,000–500,000 | 面向国资与大型制造（报告 §6-卖点6 的真需求） |

**为什么按连接器而不按席位**：席位制与 AI 的价值方向相反（报告 §4.4 第一条）。按连接器收费则与价值同向——客户连的系统越多，我们能闭环的事越多，收费也越合理；且连接器数量是**可数、可审计、不可争议**的，天然避免归因纠纷。

#### （2）结果费：三个可选结果单元，客户自选一个主锚点

| 单元 | 定义 | 计价方式 | 适用客户 |
|---|---|---|---|
| **R1 有效对账行**（默认，已拍板） | 自动放行且结论正确的对账行（口径见 07《商务口径与 POC 验收》§1.1，本地文档不入库） | 有效对账行 × 单行单价；工时**仅作封顶参照与内部价值测算**，不参与结算 | 几乎所有客户，口径最硬 |
| **R2 差异收敛** | 对账差异金额的下降 | 减少的差异金额 × 12%（剔除"本来就不会付"的部分） | 差异率高的客户，需双方共同确认口径 |
| **R3 周期达成** | 月结天数 / 三单直通率达标 | 阶梯奖金（如月结 ≤10 天奖 ¥80k，≤8 天再奖 ¥120k） | CFO 主导、目标明确的客户 |

**为什么默认 R1**：R2 的归因争议最大（"这些差异我们本来也能发现"），R3 的达成受客户自身流程影响大（我们不可控）。R1 的口径最硬：**行可逐行抽查、可逐行取消计费资格，客户不信时抽 50 行一起看即可**；工时不可核，只作年度封顶参照与内部价值测算，**不作计费单元**（完整口径与「1:1 扣减」定义见 07《商务口径与 POC 验收》§1.1、§2.3）。

> **计费单元已拍板**：合同、报价单、标书只允许出现「有效对账行」口径；任何「按工时计费」的表述均为过期版本。
>
> **计量与争议**：结果费按月出计量表，客户 10 个工作日内确认、30 天争议期，逾期视为确认；错放行只取消该行计费资格，已过争议期原则不追溯（系统性错误除外）。完整规则见 07《商务口径与 POC 验收》§2.2，合同附件须整节引用。
>
> **系统支撑状态：未实现**。计量表端点、以及「按行输出有效 / 不计费状态」的查询均未建设，PRD M16（FR-1601–1604）仍为需求；系统内推送与逐行下钻同样未实现。**过渡方案**：由交付方（客户成功 / 实施）在每期关账后 3 个工作日内，按 07 §2.2.1 字段从审计台账导出 CSV，经我方财务复核 + 客户计量确认人书面确认后，**作为过渡期的合规计量依据**；每月固定 1 次，CSV 与审计台账按批次号可逐项对账，计量表首页须标注「过渡口径，非系统自动计量」，送达以邮件发送并在首页记录送达日期，M16 上线后切换。不得由销售单人导出，也不得口头报数。

**R2 的护栏**：必须剔除"争议差异"（供应商本就不会被支付的部分），且只对**连续两个期间稳定下降**的部分计费，防止一次性波动导致账单跳变。

#### （3）一次性：数据诊断 + 首个闭环上线

| 项 | 假设价格 | 周期 | 说明 |
|---|---|---|---|
| 数据体检（Data Check） | ¥80,000–150,000 | 2 周 | 输出可修复清单；**不达标不建议签约**，兼作准入筛选器 |
| 首个闭环上线 | ¥200,000–400,000 | 4–6 周 | 含连接器对接、模板配置、影子运行、培训 |
| 超出范围的定制 | ¥3,000–5,000 / 人天 | — | 每客户定制上限 15 人天，超出需产品委员会批准（防止做成项目制） |

数据体检的产品化依据是报告 §6-卖点3：数据质量是 AI 项目失败首因之一，而大厂卖 AI 不承担数据治理。但**我们不把它当主卖点，而当销售工具**——它的作用是让"这个客户能不能做"在收钱之前就有答案。

### 1.3 一个客户的账（假设：营收 8 亿的电子组装企业，3 个工厂）

| 项 | 金额 | 备注 |
|---|---|---|
| 平台订阅（5 连接器 × 3 组织） | ¥ 300,000 | 12 万 + 4 万 + 8 万 |
| 结果费（R1：有效对账行约 12,000 行/年 × 单行单价，示例 ¥3.6/行，单价待确认） | ¥ 43,200 | 约 52 家供应商 × 12 期 × 约 19 行/家/期；总额沿用原测算，仅换算口径 |
| 年度封顶 | ¥ 900,000 | 实际远低于封顶 |
| **首年经常性收入** | **¥ 343,200** | 不含一次性 |
| 一次性（诊断 + 上线） | ¥ 350,000 | 首年一次性 |
| **首年合同额（ACV）** | **¥ 693,200** | — |

**单位经济假设（待验证）**：订阅毛利率目标 ≥ 75%（主要是算力与运维）；实施毛利率首年 30–40%，标准化后目标 50%；单客户回本周期（CAC 回收）目标 ≤ 14 个月。

### 1.4 定价的四个"不做"

1. **不做免费版/Freemium**：我们的客户是 3 亿以上营收的制造企业，免费版只会吸引做不了的客户，且私有化成本高。
2. **不按 token 计价**：把模型成本转嫁给客户，等于复制我们正在攻击的问题。
3. **不承诺"降本百分比"作为计费基数**：降本的口径几乎无法达成一致，坚决不用。
4. **不做"成功后付全款"**：必须保留平台订阅作为底座，否则现金流无法支撑 6–18 个月的销售周期（报告 §4.2）。

## 2. 交付模式

| 形态 | 目标客户 | 部署 | 占比目标（Phase 2） |
|---|---|---|---|
| **私有化全量** | 国资、大型制造、数据不出域要求 | 三平面全在客户侧 | 30% |
| **混合（默认）** | 中型制造 | 数据面在客户侧，控制面托管 | 60% |
| **SaaS 多租户** | 小型客户（Phase 3 才开） | 全托管 | 10% |

**为什么默认混合**：报告 §5.1-3 与 §6-卖点6 都指向"数据不出域"是制造与国资客户的硬约束；但全私有化会让版本升级与运维成本失控。混合模式把业务数据留在客户侧，只让元数据出域，是成本与合规的平衡点。

## 3. 实施路径（把实施做成产品，而不是做成顾问项目）

报告的核心事实：实施成本高、超支 189%、一线不用是失败首因（§4.3）。如果我们的实施也靠人天堆，那我们就复制了客户的痛苦。

### 3.1 四步法

| 步骤 | 周期 | 交付物 | 收费 | 退出条件 |
|---|---|---|---|---|
| **① 诊断** | 2 周 | 数据体检报告、系统开放度评估、可闭环场景清单、ROI 测算 | 一次性 | 数据质量不达标或系统完全封闭 → 不进入下一步 |
| **② 单点闭环** | 4–6 周 | 1 个场景（对账）× 1 个供应商群 × 1 个期间跑通，影子运行 + 灰度写入 | 一次性 | 差异率改善 ≥ 20%，否则免费延期或退款 |
| **③ 扩展** | 每季度 | 场景扩展（A3/A4/A8）、组织扩展（多工厂）、连接器扩展 | 订阅增量 | 每季度复评 ROI |
| **④ 托管运营**（可选） | 持续 | 我们代跑月度对账与月结辅助，客户只做复核 | 订阅 × 1.3 | 客户可随时收回 |

### 3.2 实施的产品化手段（决定毛利）

1. **行业模板**：电子组装行业的科目映射、供应商对账模板、单位换算规则、常见差异归因规则，做成开箱即用的配置包。第二个客户起复用率目标 ≥ 70%。
2. **连接器兼容性矩阵**：每个 ERP 版本一套已验证的字段映射与限流参数，新客户直接套用。
3. **Agent 配置而非开发**：客户差异只允许通过"规则参数 + 提示词模板 + 字段映射"三种方式适配，不允许改代码。
4. **影子运行自动化**：上线前 2 个周期的比对报告自动生成，减少顾问驻场时间。
5. **定制配额**：单客户定制 ≤ 15 人天，超出走产品需求流程。这是防止公司退化成实施商的关键制度。

## 4. MVP：到底做哪几条

### 4.1 做（六条，缺一不可）

| # | 内容 | 为什么必须在 MVP |
|---|---|---|
| 1 | **A1 对账 Agent** | 楔子本体，验证"跨系统写入"是否成立 |
| 2 | **A2 单据录入 Agent** | 对账的上游，没有干净数据就没有可信对账 |
| 3 | **Agent 工单 + 审计 + 回滚 + 双人复核** | 安全评审的准入条件，没有它 CIO 不会签 |
| 4 | **连接器 3 个可用 + 3 个在建**（用友 U8/YonSuite 或现有国产 ERP、Odoo/ERPNext、MES 通用 REST、企微、文件通道、SAP 视客户） | 没有连接器就没有跨系统 |
| 5 | **七个界面**：工作台、对话入口、Agent 任务详情、复核审批、异常队列、连接器管理、报表与结算，外加 IM 卡片 | 没有界面，Agent 的价值无法被看见与批准 |
| 6 | **基线采集与价值仪表盘 + 私有化部署包** | 结果计费的前提；大客户准入的前提 |

### 4.2 明确不做（同样是产品决策）

| 不做 | 原因 | 什么时候做 |
|---|---|---|
| 总账、税务、资金支付、工资、固定资产 | 会让我们变成 ERP，承担会计责任（见架构 §4.3 硬边界） | 永远不做 |
| 自研 MES 执行、自研 APS 求解器 | 用现有系统 + Frepple，MVP 阶段自研等于把资源投在红海 | 排程用 Frepple（Phase 3） |
| 报价 Agent、排程 Agent、异常处置 Agent | 依赖干净的主数据与稳定的对账账，顺序不能反 | Phase 3 |
| W3 写入（付款执行、凭证过账、发票认证） | 安全评审过不了，一次事故毁掉全部信任 | Phase 3 视审计结论 |
| Agent 市场 / 客户自助搭 Agent | 会把我们变成集成平台，客户也没这个能力（报告 §2 型 C 的天花板） | Phase 4 之后，且只对伙伴开放 |
| 移动 App | IM 卡片已覆盖 | 不做 |
| 多行业模板 | 一个行业做不透，两个行业都做不好 | Phase 2 起每年加一个 |
| 多语言 / 多币种报表 / 海外合规 | 与目标客户无关 | 不做 |
| 与封闭系统的 L3 界面 RPA | 维护成本高、易被厂商改版打断（报告 §5.2 厂商配合度） | Phase 3 仅对战略客户 |

### 4.3 MVP 验收标准（可量化，达不到就不进 Phase 2）

| 维度 | 指标 | 阈值 |
|---|---|---|
| 客户 | 付费灯塔客户数 | ≥ 3（同一行业，且都满足"≥2 套异构系统"画像） |
| 效果 | 对账差异率相对基线下降 | ≥ 30%（至少 2 家达标） |
| 效果 | 单供应商对账工时下降 | ≥ 60% |
| 效果 | 首个闭环上线周期 | ≤ 6 周（从诊断结束起算） |
| 质量 | 写入成功率 | ≥ 99.5% |
| 质量 | 回滚成功率（可回滚场景） | 100% |
| 质量 | 审计覆盖率（写动作有工单与前后像） | 100% |
| 安全 | 越权写入事件（红队测试 + 生产） | 0 |
| 安全 | 安全评审通过率（接触的客户中） | ≥ 50% |
| 商业 | 结果费口径被客户书面确认 | 3/3 |
| 组织 | 单客户定制人天 | ≤ 15 |

## 5. 三阶段路线图

### Phase 1｜M0–M6：证明"跨系统写入"能成立（MVP）

**目标**：在 3 家电子组装客户跑通对账闭环，拿到第一份可验证的效果数据与第一份安全评审通过记录。

| 月份 | 里程碑 |
|---|---|
| M0–M1 | 诊断产品化（体检模板 + 报告生成）；3 个连接器可用（国产 ERP、MES、文件通道）；Agent 工单与状态机跑通 |
| M2 | A2 单据录入上线（影子）；审计台账与回滚演练（含故障注入） |
| M3 | A1 对账上线（影子）；工作台/审批/异常队列可用；第 1 家客户进入灰度 |
| M4 | 第 1 家客户灰度写入转正式；基线采集完成并签基线协议 |
| M5 | 第 2、3 家客户上线；私有化部署包交付 |
| M6 | Phase 1 验收；定价与结果费口径复盘 |

**Go/No-Go 门槛（进 Phase 2 必须全部满足）**：
1. 3 家付费客户，且至少 2 家达到差异率下降 30%。
2. 生产环境 0 起越权写入、0 起不可恢复的数据污染。
3. 单客户实施人天 ≤ 45（否则毛利模型不成立）。
4. 至少 1 家客户愿意签第二年（续费意向书）。

**团队假设**：产品 2、Agent/算法 4、后端与连接器 4、前端 2、实施 3、售前 1。

### Phase 2｜M7–M12：从单点到多场景，把计费跑通

**目标**：把"对账"扩展成"月结周期"，把结果计费真正收上来，验证跨客户复用率。

| 月份 | 里程碑 |
|---|---|
| M7 | A8 月结辅助上线（暂估/冲回/凭证草稿）；连接器扩到 8 个 |
| M8 | A4 库存与齐套上线（W0/W1）；多组织（多工厂）支持 |
| M9 | A3 采购比价上线；行业模板 v1（电子组装）复用率验证 |
| M10 | 结果费首次结算（R1 单元）；价值仪表盘对外 |
| M11 | 第二个行业模板（装备制造）试点 1 家 |
| M12 | Phase 2 验收；渠道伙伴模式设计 |

**验收标准**：
- 付费客户 ≥ 10 家，NDR（净收入留存）≥ 110%。
- 结果费收入占比 ≥ 20%，且客户对账单争议率 ≤ 10%。
- 第二客户起的实施人天 ≤ 25（模板复用率 ≥ 70%）。
- Agent 复核驳回率 ≤ 15%，差异归因准确率 ≥ 85%。
- 月结天数中位数下降 ≥ 3 天（A8 的硬指标）。

### Phase 3｜M13–M18：从"财务运营"走向"制造执行周边"

**目标**：进入排程与异常处置（制造侧），补齐"交付风险闭环"，验证私有化大客户与渠道。

| 月份 | 里程碑 |
|---|---|
| M13 | A5 排程 Agent（Frepple 内核 + LLM 解释，严格 W0） |
| M14 | A6 异常处置 Agent（W1，跨 ERP/MES/委外） |
| M15 | A7 报价 Agent（成本模拟）；私有化标准版（一键部署） |
| M16 | 渠道伙伴首批 3 家（区域 ERP 服务商）；实施认证体系 |
| M17 | 第三个行业（汽车零部件）模板；W3 写入的安全评估（不承诺上线） |
| M18 | Phase 3 验收与下一阶段规划 |

**验收标准**：
- 付费客户 ≥ 25 家，ARR 达到内部目标（按 Phase 2 的 ARPU 与增速推算）。
- 排程 Agent 采纳率 ≥ 60%（计划员实际采纳的方案占比）。
- 异常闭环时长下降 ≥ 40%。
- 渠道贡献收入占比 ≥ 15%。
- 私有化客户 ≥ 3 家（验证国资/大型制造路径）。
- 至少 1 个原厂发布同类能力，且有明确的应对话术与差异化验证（窗口监控，见定位文档 §6.3）。

## 6. 商业模式的三个脆弱点（提前说）

1. **结果费的天花板与地板**：如果客户效果很好，我们收得少（封顶）；如果效果不好，我们收不到。这个结构对客户友好、对我们不友好。缓解：平台订阅必须覆盖成本，结果费只作为"价值证明"而非主要收入来源（目标占比 ≤ 40%）。
2. **销售周期与现金流**：大型制造决策链 6–18 个月（报告 §4.2），而我们要先付诊断成本。缓解：诊断收费（不免费）、只对通过筛选的客户投入售前、优先做已有 ERP 服务商关系的客户。
3. **"你们和集成商有什么区别"**：这是最常见的质疑。答案必须具体：集成商交付项目，我们交付产品化的执行层与审计台账；集成商按人天收费，我们按连接器与结果收费；集成商不承担回滚责任，我们承担。这三句话要写进销售手册第一页。
