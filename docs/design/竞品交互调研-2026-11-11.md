# 高端竞品前端交互调研（2026-11-11）

> 范围：SAP S/4HANA + Joule、Oracle Fusion Cloud ERP（Redwood）、NetSuite、Workday Financials、Microsoft Dynamics 365（Copilot）；Rillet、Numeric、Vic.ai、Zip、Puzzle；用友 BIP / YonSuite、金蝶云苍穹；交互标杆 Linear、Stripe Dashboard、Vercel、Retool。
>
> 只研究**交互层**：首屏信息架构、信息密度、AI 嵌入方式、差异与证据呈现、决策界面、状态语言、视觉尺度。不抄卖点文案，不把「有 AI」当结论。
>
> 目标基线：main `6585831`（派单时 `3f4e9c0`，其后 main 前进 6 个提交；本调研与改造基于当前 main）。

## 一、结论（10 条以内）

### 1. 首屏是「今天要做什么」，不是「系统有什么功能」
- **对方怎么做**：Rillet 的 Launchpad 把运营队列与 KPI 放在同一个 CFO 视图；Puzzle 的 Tasks 卡按影响与紧急度排序「真正需要你处理的事」；Workday 把 Inbox 固定在右上角并显示待办数；SAP Fiori 的 launchpad 以角色和场景组织入口。高端产品的首页几乎都不是模块菜单，而是**决策队列 + 范围上下文**。
- **我们怎么做**：工作台首屏改成三段式——顶部 scope/新鲜度条，中部「待你决策」队列（审批、W3、争议、失败补偿），右侧「风险雷达 + 对账摘要」。功能入口退到左侧导航，不再占用首屏。

### 2. 一级导航在左侧，顶部只放 scope、搜索与身份
- **对方怎么做**：Stripe Dashboard、Linear、Vercel、Retool 都是左侧持久导航 + 顶部全局条；Oracle Redwood 26B 继续扩大左侧导航与角色化首页；用友 BIP 的导航设置明确支持左侧导航/底部菜单与两级结构；金蝶苍穹的 BOS 页面同样以应用菜单为一级。NetSuite 的「逐步揭示」用固定窄头部降低视觉噪音。
- **我们怎么做**：把现有顶部横排导航改成 232px 左侧栏（可折叠到 64px 图标栏），顶部只保留面包屑/页面标题、scope 选择器、⌘K 搜索、通知、身份。二级页面用「返回 + 当前对象」的上下文头，不再重复一级导航。

### 3. 高密度表格是财务产品的基本盘：40px 行高、冻结首列、右对齐数字
- **对方怎么做**：Linear 明确「信息密度优先于留白，细节在 hover 时揭示」；Stripe Dashboard 的金额列使用 `tnum`（等宽数字）并右对齐；NetSuite 的列表与 portlet 默认紧凑、可折叠；SAP Fiori 的 responsive table 在宽屏展示多列、窄屏转卡片。高端产品不会用大卡片列表承载 20 条以上同构记录。
- **我们怎么做**：工单、差异、计量明细统一为「紧凑表格 + 窄屏卡片」双形态：表头 36px、行高 40–44px、首列冻结、金额列右对齐并加 `tabular-nums`、状态列固定宽度。列表一屏目标 ≥14 行（1440×900），不再一屏 3 张大卡。

### 4. AI 的默认形态是「右侧常驻 + 先草稿后确认」，不是聊天框孤岛
- **对方怎么做**：SAP Joule 的答案动作、Steps/Sources/References 收在右侧面板；SAP Fiori 的 side panel 明确定位为「页面/条目的附加上下文与交互工具」，展开时挤压主内容；Dynamics 365 Copilot 在业务工作区里生成摘要与邮件草稿，由人确认；Business Central 的 Payables Agent 先给出票据草稿，再由主管复核。共同点是：**AI 不直接写业务，只产出可审阅的草稿**。
- **我们怎么做**：全局右侧增加可收起的「助手」栏，只做三件事：解释当前页数字、给出下一步入口、生成待确认的处理草稿。所有草稿必须显示「待确认」并能一键跳到对应人工动作；不新增写接口、不自动执行。AI 接口未进入 C16，本轮只做交互壳与确定性建议，契约缺口记录在案。

### 5. 命令面板是高端工作台的「第二导航」
- **对方怎么做**：Linear 把 ⌘K 做成导航、搜索、动作的统一入口；Retool 的 Command Palette 支持跳转应用、查询、资源与执行命令；Vercel 的 Dashboard 也以全局搜索/跳转降低导航层级。
- **我们怎么做**：实现 ⌘K / Ctrl+K 命令面板：搜索工单号、批次、差异、页面；支持「发起对账」「打开审批」「切换密度」等动作；方向键选择、Enter 执行、Esc 关闭。移动端用顶部搜索按钮触发同一面板。

### 6. 差异用「并排 + 变更单元格高亮」，证据用「编号链 + 原始坐标」
- **对方怎么做**：Stripe 的对比视图把变化项放在主列、静态元数据放右列；审计/对账类产品普遍采用 field-level diff（字段、我方、对方、差额、原因）而不是整段文本；证据以文档号 + 页码 + bbox 的形式可下钻。SAP Joule 把 Sources 放在独立右侧面板，避免证据与结论混在一起。
- **我们怎么做**：差异详情改成「左：并排字段 diff（变更单元格琥珀底、差额红/绿）+ 右：证据链」；证据按 1/2/3 编号，展示系统、单据号、字段、页码、bbox，并保留原始 JSON 折叠。移动端上下堆叠，证据在 diff 之后。

### 7. 要人做决定的界面：队列 + 详情 + 固定决策条
- **对方怎么做**：Workday 的 Inbox 是任务队列，点开进入任务上下文；Zip 的 intake/审批按金额、类别、实体路由到队列；Puzzle 的任务卡按影响排序；Stripe 的争议/退款也是队列 + 右侧详情 + 底部动作。高风险动作不放在长页面底部，而是随详情固定的操作条。
- **我们怎么做**：审批页改为「左队列（可按风险/等级/金额筛选）+ 右详情 + 底部固定决策条（驳回/通过）」，显示当前角色、缺哪个角色、金额与 W 等级；键盘 A=通过、R=驳回（聚焦输入框时不触发）。W3 直接给不可执行说明，不提供通过按钮。

### 8. 状态语言必须覆盖「加载 / 空 / 错 / 部分失败 / 长任务」
- **对方怎么做**：Linear 用 120–180ms 的动效与骨架表达状态变化；Vercel 的部署页把 queued/building/ready/error 做成阶段条；NetSuite/Workday 的空态会告诉用户下一步；SAP Fiori 对部分失败给出可操作的错误面板而不是一个红点。
- **我们怎么做**：保留现有 6 类错误态与空态语义，但统一为「状态条 + 主区骨架 + 可点击下一步」；对账批次增加阶段进度条（取数→匹配→差异→计量）与部分失败清单；长任务按钮进入 pending 时显示进度文案，不用只变灰。

### 9. 视觉：中性底 + 单一强调色，圆角/阴影克制，金额必须等宽
- **对方怎么做**：Linear 的「单一强调色 + 导航退后」；Stripe 的 indigo 强调与 `tnum` 金额；Vercel 的黑白灰 + 状态色；Oracle Redwood 提供浅色/深色主题但内容层保持中性。高端感来自**对比度、对齐、留白节奏**，不是更多颜色和阴影。
- **我们怎么做**：设计 token 改为：中性 slate 底、indigo-600 单一强调色、语义色只用于状态；圆角 8/12/16 三档；阴影只保留 1px 边框 + 极轻浮层；全站数字 `font-variant-numeric: tabular-nums`，金额右对齐；正文 13px、辅助 11–12px、标题 16–20px。

### 10. 空数据不是「改完了」，demo 必须有可信的业务量
- **对方怎么做**：高端产品的 demo/试用环境默认带一套完整样例数据（多供应商、多状态、多币种/税率），首屏就能看到队列、差异和金额；空态是首次使用的引导，不是默认状态。
- **我们怎么做**：mock 数据补齐到「可演示」：≥18 张工单覆盖 8 个状态与 W1/W2/W3、≥8 条审批待办、≥10 条差异覆盖 6 类差异、计量 64 行保持 59/3/2 桶结构且金额非 0。mock 与真实接口共用同一渲染路径，不为 mock 写分支；正式演示数据由数据流替换时不需要改页面。

## 二、可执行改造清单

> 约定：`P0` = 本轮必须完成、可直接演示；`P1` = 本轮尽量完成；`P2` = 后续迭代。
> 「改成什么样」写到能照着施工；「为什么」对应上面的结论编号。

### P0-1 全局壳：左侧导航 + 顶部上下文条 + 右侧助手
- **页面**：`web/src/components/AppShell.tsx`、`web/src/styles.css`
- **改成什么样**：
  - 桌面：左侧 232px 固定导航（品牌区、4 个一级入口、底部 scope/环境徽标），可折叠为 64px 图标栏；右侧 340px 助手栏可收起；主区最大宽度 1440px。
  - 顶部 56px：左侧移动端菜单按钮 + 面包屑/页面名；右侧 scope 选择器、⌘K 搜索按钮、通知、身份菜单、设置。
  - 移动端（<1024px）：侧栏变抽屉（遮罩 + 从左滑入），助手变全屏 sheet；主区单列，390px 无横向滚动。
  - 保留「MOCK 数据 / 真实 API」徽标与连接设置面板。
- **为什么**：结论 1、2、4、5。首屏让位给决策队列，导航与工具退后。
- **验收**：1440px 首屏可见左侧导航 + 内容 + 助手；390px 打开/关闭抽屉不溢出；⌘K 可打开命令面板。

### P0-2 命令面板（⌘K）
- **页面**：新增 `web/src/components/CommandPalette.tsx`，挂载在 `AppShell`
- **改成什么样**：遮罩 + 居中 560px 面板；输入即过滤；分组「页面 / 工单 / 对账 / 动作」；↑↓ 选择、Enter 跳转、Esc 关闭；空结果显示「没有匹配，试试工单号 T-1001」。动作至少包含：工作台、工单、审批、对账、发起对账、打开连接设置、切换紧凑密度。
- **为什么**：结论 5。高端工作台的第二导航，减少鼠标层级。
- **验收**：`Ctrl/⌘+K` 打开；输入「审批」回车进入 `/approvals`；Esc 关闭；移动端顶部搜索按钮可打开同一面板。

- **页面**：`web/src/pages/TicketDetailPage.tsx`

### P0-6 审批：队列 + 详情 + 固定决策条

## 附录：`VITE_USE_MOCK=false` 的真实接口核对（2026-11-11）

结论先说：**页面没有 mock 专用分支，切开关即可走真实接口；但要达到截图里的信息密度，有三个数据/会话前提，缺一个就会「空但不报错」。**

| 页面 | 真实接口 | 实现位置 | 切真实后的空态风险 |
| --- | --- | --- | --- |
| 工作台 | `GET /v1/auth/session` → `GET /v1/tickets?limit=100`、`GET /v1/approvals/pending?limit=20` | `apps/api/routes/auth.py`、`apps/api/routes/tickets.py:52`、`apps/api/routes/approvals.py:67` | 会话返回 401 时 KPI 显示「—」而不是 0，并提示「当前未启用演示会话」；见下方前提 1 |
| 工单列表 / 详情 | `GET /v1/tickets`、`GET /v1/tickets/{id}` | `tickets.py:52` / `:86` | 工单数少于 20 时表格只剩几行，不是渲染故障 |
| 审批 | `GET /v1/approvals/pending`、`POST /v1/approvals/{id}/{approve\|reject}` | `apps/api/routes/approvals.py:67` / `:95` | 会话角色与所需角色无交集时队列为空；见前提 1 |
| 对账批次 | `POST /v1/recon/runs`、`GET /v1/recon/batches`、`GET /v1/recon/runs/{id}`、`.../diffs`、`.../diffs/{id}` | `apps/api/routes/recon.py` | 批次列表对没有计数投影的旧批次返回 `null`，页面渲染成「—」；见前提 2 |
| 计量表 | `GET /v1/metering/batches/{id}/statement` | `metering.py:22` | 依赖真实 batch_id |
| 审计证据 | `GET /v1/audit/tickets/{id}/images`、`.../chain`、`/v1/audit/export` | `audit.py:18` / `:48` / `:66` | 未执行过写入的工单本来就没有影像；见前提 3 |

**前提 1：会话身份。** `/v1/approvals/pending` 只返回「scope 内、待审批、发起人不是当前用户、所需角色与当前用户角色有交集」的工单。身份只来自 `GET /v1/auth/session`（#107 `1f584ef`，实现见 `apps/api/routes/auth.py`、`apps/api/demo_session.py`），前端已删除 `VITE_SESSION_ROLES` / `VITE_VIEWER_ID`，**不要再配这两个变量**。

启用方式（部署期，双闸）：`ERP_APP_ENV=demo` 且 `ERP_DEMO_SESSION_ENABLED=true`，并按 `deploy/smart-erp/.env.example` 填写 `ERP_DEMO_SESSION_IDENTITIES`（JSON 数组，每条一个身份：`token` / `user_id` / `tenant_id` / `roles` / `org_ids` / `periods` / `system_ids`）；缺字段、坏 UUID、令牌或 user_id 重复、空映射都会启动失败。多身份用于演示「发起人 ≠ 审批人」的双人复核：两枚令牌分别对应两人，审计里能看到不同操作人。服务端没有签发端点，前端把对应身份的令牌填进「连接设置」（或构建期 `VITE_SESSION_TOKEN`）即可换回 `{user_id, tenant_id, roles}`。

关闭或令牌无效时端点返回 401，前端显式降级：工作台 KPI 显示「—」并提示「当前未启用演示会话」，而不是把 401 渲染成「0 条待办」。

**前提 2：批次入口。** 批次列表走 `GET /v1/recon/batches`（#108 `ea75caf`，键集分页），页面不再需要粘贴 `batch_id`，也不再依赖 `localStorage` 的「本机最近批次」。两个边界按契约原样渲染：没有计数投影的旧批次，`line_count/diff_count/diff_amount` 为 `null`，显示「—」并标注「未投影（非 0）」；越权返回 403 且响应体没有 `items`，走错误面板，不能当空数组。

**前提 3：证据区。** 只有已执行过步骤（`succeeded` / `compensated` / `rolled_back`）的工单才有审计影像。demo 数据集必须包含至少若干「执行中 / 已完成 / 已回滚」工单，否则详情页证据区会合法地显示空态。

**mock 与真实路径是否同一份定义：** 不是。`client.ts` 负责拼路径，`mock.ts` 按路径分段匹配，历史上因此漂移过两次（`/v1/recon/runs/{batch}/diffs`、`/v1/audit/tickets/{id}/images|chain`）。本次已把路径构造器从 `client.ts` 导出，无路径参数的读接口也收成常量（`SESSION_PATH` / `RECON_BATCHES_PATH` / `TICKETS_PATH` / `PENDING_APPROVALS_PATH`），并新增 `tests/web/api-mock-routes.test.ts`（13 条，含批次 `null` 边界）用构造器生成路径直接打 mock：client 一改路径、mock 不认就红，漂移不会再静默通过。
