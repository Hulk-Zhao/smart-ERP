# 对账引擎行为变更记录（apps/recon）

> 适用版本：`1d759af`（分支 `feat/recon-persistence`，随 PR #32 合入 main）
> 用途：给评审看的变更与计费口径摘要。本文件**不含任何夹具放行率数字**——金标准集为自造、与标注同源，不构成泛化证据，相关数字只留在本地未入库文档中。

---

## 1. 会改变对账输出的六项改动

| # | 改动 | 改动前 | 改动后 | 影响已承诺口径？ |
|---|---|---|---|---|
| 1 | `unparseable` 行整批转人工 | 金额/数量脏值抛 `ValueError`，整批无法对账 | 行级「不可解析」+ 整批待人工，其余行照常对账 | **是，兑现既有承诺** |
| 2 | unit_guard 对直配层生效 | 直配只看单据号，单位不参与判定 | 单位不同必须换算且数量、金额同时闭合，否则只给候选 | **是，收紧** |
| 3 | 重复计费键改为「同供应商+期间+单据号+物料」 | 7 字段全等去重，同单号被改动的一行漏成「缺单」 | 同单号同物料第 2 行起判重复并列出冲突列；跨单号整行全等仍判重复 | 是，更严 |
| 4 | 新增聚合匹配层（拆单/合并） | 只做一行对一行，拆单第二行必成缺单 | 合计双闭合的拆单自动放行并标 `aggregated`；合并一律待人工 | 是，新增放行路径 |
| 5 | 评分前先做单位换算 | 直接用供应商原始数量/单价算相似度 | 换算到我方单位口径再比；不可换算按中性降权并区分原因 | 是，不扩大放行风险 |
| 6 | 新增「金额舍入容差」类别 | 角级取整差无类可归，批次转人工 | 单行与整批累计均在容差内则放行并留痕；超限仍转人工 | 是，新增放行类别 |

### 1.1 `unparseable` 行整批转人工（重点）

- **改动前**：`build_request` 直接调 `to_decimal`，脏值抛 `ValueError`，调用方拿不到 `ReconResult`，整批失败。
- **改动后**：逐字段捕获为 `ParseIssue{ref, side, field, raw}`；该行从匹配中摘出，行状态 `不可解析`；同单号同行号的对手行一并摘出（避免「一方不可解析、另一方被判缺单」的假差异）；整批转 `待人工复核`；其余可解析行照常对账。
- **是否影响已承诺口径**：**兑现既有对外承诺**（`unparseable` 行整批转人工、不向外抛），不新增口径。新增两点为：对手行一并摘除、不可解析行必计入待人工计数。不静默当 0、不猜。

### 1.2 unit_guard 对直配层生效（重点）

- **改动前**：直配只判「同供应商 + 同单据号」，取 `same_line[0]`，置信度 1.00，单位不参与判定；`100 BOX` 与 `100 PCS` 会被当作同一笔自动放行。
- **改动后**：直配同样过 `unit_guard`。单位不同（仅忽略空白与大小写）必须命中主数据换算，且换算后**数量与金额同时闭合**；不满足则置信度封顶 0.65，只给候选，状态 `候选待人工`，原因码写明「单位不一致」及可核对数字（含 `[UNCONVERTIBLE]`）。
- **是否影响已承诺口径**：**是，属收紧**。自动放行率会下降、待人工上升，验收结论须记为「预期收紧」，不得当成回归。

### 1.3 重复计费键改四元组（重点）

- **改动前**：仅按 `(供应商, 期间, 物料, 单位, 数量, 单价, 金额)` 全等去重。同单据号下被改动过的一行（如单价 10→10.2）识别不到，反而落成「缺单」。
- **改动后**：两个维度。① 同 `(供应商, 期间, 单据号, 物料)` 的第 2 行起一律判 `重复计费`，内容不同则标冲突并逐列写出冲突（如「单价 10.0000→10.2000」）；② 跨单据号的整行全等仍判重复。
- **是否影响已承诺口径**：是，方向更严。**原本被判重复的单据不会被重新计入**——旧键命中的行在新实现的第二维度仍按同一组字段判重复，旧集合是新集合的子集；新增识别的是旧实现漏掉的「同单号内二次列示」。

### 1.4 聚合匹配层（拆单 / 合并）

- **改动前**：只做一行对一行，拆单的第二行必然落成「供应商未匹配」。
- **改动后**：多对一（拆单）在同供应商 + 物料 + 期间 + 单位下，合计与单行**数量与金额同时闭合**才自动放行，`match_type=aggregated` 并带 `aggregate_refs`，人工可区分直配与聚合；一对多（合并）拆分口径不唯一，一律 `待人工`。
- **是否影响已承诺口径**：是。新增一条自动放行路径，仅限「合计双闭合」的拆单。

### 1.5 评分前先做单位换算

- **改动前**：直接用供应商原始数量与单价计算相似度，单位差异把分数压到阈值以下，跨单位行恒为候选。
- **改动后**：先按主数据换算到我方单位口径再比（数量 ×系数、单价 ÷系数）；换算不可得时按中性分降权，并在候选原因里区分「不可换算」与「相似度低」。
- **是否影响已承诺口径**：是，识别更准；闸门未放宽，换算不闭合仍走 1.2 的封顶。

### 1.6 金额舍入容差

- **改动前**：金额差在按角取整的物理误差内，但无类可归，进「无法归因」→ 批次待人工。
- **改动后**：单行 ≤ `tolerance.rounding`（默认 0.05 元）、整批累计 ≤ `rounding_batch_limit`（默认 1.00 元）且累计占比 ≤ 0.5% 时，记 `DiffType.ROUNDING_TOLERANCE`，不生成差异单、不计入差异金额与差异率，批次可自动放行；超限则 `rounding_escalated` 转人工。
- **是否影响已承诺口径**：是。新增放行类别，且「不计入差异率」会改变对外披露的差异率口径；该类别在差异明细中可见，可审计。

## 2. 计费口径决定（已定）

### 2.1 有效对账行 = 行级 auto，含已自动归因的差异行

- 定义：`status=已匹配` 且 `match_type∈{exact, fuzzy, aggregated}` 且 `needs_manual=false`；包含 `单价不一致` / `数量不符` / `税率口径` / `报废未扣` / `金额舍入容差` 等已自动归因的行。分母剔除整批 `无法对账` 的行。
- 理由：这些行已完成配对、比价、归因与证据留痕，人工接手成本已被消除；无差异行占比为 0 只说明该批业务本身有差异，不代表引擎未产出。
- **不以「无差异行」作为计费基数**，该指标仅作内部质量度量，不进入合同。

### 2.2 批次未放行但行已自动匹配的，照计

- 计费单元是**行**，不是批次。批次 `待人工复核` 只表示该批仍有未决项，不影响其中已自动匹配行的计费。
- **合同兜底句（原样写入合同/计费附件）：「计费不以批次放行为前提。」**

### 2.3 舍入容差行计费

- `DiffType.ROUNDING_TOLERANCE` 行已自动放行、未生成差异单，**计入有效对账行**。
- 理由：该类行已完成配对与金额校验，差额落在按角取整的物理误差内，结论与无差异行等价，仅多一条可审计的容差留痕。整批累计超限转人工的部分不计费。

### 2.4 反向减项

- 只认两类，**按行扣减**：`confirmed_wrong`（自动放行结论经复核确认错误）、`customer_reason`（客户侧原因导致该行无效）。
- **系统性错误不逐行扣减**，走整体追溯（整批重跑 / 退费），避免逐行扣减掩盖系统性问题。
- 这两个标记由计费服务侧作为回填事件产出（已批准的 schema 追加），`apps/recon/` 不产出、也不需要产出对应字段，属预期边界。
